# 存量错误出口迁移与验收

本次任务明确改造请求错误反馈时阅读。目标是所有业务请求错误 Toast 复用应用根层的一个出口与队列，包负责计时、定位和卡片，宿主负责事件身份、安全文案及关闭后的队列清理。页面内常驻错误态与普通成功、本地校验提示按各自用途保留。

## 迁移清单

1. 搜索公共错误/权限组件、所有 `message.error`、`toast`、通知容器、关闭计时器及其包装函数，沿调用方清点实际入口。至少检查权限/Schema 首次加载、列表读取、保存（含单元格）、删除、关联读取、批量操作，以及已启用的 OCR、审批、AI。记录每个入口选择全局 Toast、页面内嵌错误还是本地校验；没有启用的能力不新增。
2. 复用已有全局上报函数与身份作用域队列，逐个迁移请求错误 Toast。只升级依赖、复用卡片或给旧卡片补 `duration={3}` 不算完成迁移。不要在页面旧消息容器里再创建一个全局错误队列，也不要为不同业务各挂 viewport。将旧卡片工厂及其专用样式删除；普通成功/校验消息继续使用宿主组件库。
3. 页面内错误卡在所属内容区域持续说明失败，独立 `MakeAppErrorNotice` 明确 `duration={0}`；权限 inline/page 保持常驻。若同一失败已有页面卡，不再额外弹一份相同 Toast。权限/Schema Provider 已在根出口报告的失败，页面不能再通过旧容器重复报告。
4. 同一次失败的多层上报使用同一个事件身份补充说明；不同网络尝试即使文案、Trace ID 相同也必须分配新事件，禁止仅按文案或 Trace ID 合并。包关闭时只移除对应项；不重试、重放写操作或重启权限查询。

## 门禁

新建或本次明确迁移反馈出口的 App，在原 Trace 审计之外，将 `scripts/audit-error-outlets.mjs` 与 `scripts/test-audit-error-outlets.mjs` 复制到项目本地工具目录。按宿主的包管理器接入默认测试和发布前检查，不迁移项目运行时。审计使用宿主已安装的 TypeScript 解析器，缺少解析器会明确失败，不静默跳过。

```bash
node scripts/audit-error-outlets.mjs <project-root>
node --test scripts/test-audit-error-outlets.mjs
```

第二条适用于复制到 `<workspace>/scripts`、UI 包为 `<workspace>/ui` 的布局；在 Skill 安装目录验证脚本时，用 `node scripts/test-audit-error-outlets.mjs <app-workspace>` 指定已有 TypeScript 的宿主工作区。其他布局适配测试中的解析器查找，不写入用户机器绝对路径。

审计输出全局/内嵌错误卡清单，阻断多个 viewport、全局容器外未明确常驻的独立错误卡、遗留权限 Toast，以及 catch 内直接或经局部变量将异常转换成旧文字 Toast 的明显路径。它理解 JSX、createElement、组件导入别名，排除测试、注释和字符串。宿主权限包装器以 `PermissionFeedback` / `PermissionNotice` 命名时也会检查其 Toast 用法。

异常分析按 TypeScript 符号绑定区分捕获变量、对象属性及嵌套函数同名参数，不按标识符文字匹配。未被局部声明覆盖的 单参数 JSON 解析/序列化及 URI 编解码等可确认的纯本地操作保留原校验提示。自定义或异步本地校验可在 catch 块开头写明限定声明和具体理由：

```ts
catch (error) {
  // make-error-outlet-local-validation: 仅校验当前表单字段，不执行网络请求
  message.error(error.message);
}
```

此声明只作用于该 catch，理由不能为空，并会出现在审计清单中供评审核对。已识别的 fetch/request 或请求模块导入不能通过该声明豁免；混合本地解析和请求仍按请求异常检查。未知来源保持非零并报告 `exception_toast_origin_unverified`，要求核查来源，不直接宣称它已经被证明是网络故障。宿主请求模块别名或自定义边界需按实际调用链扩展识别并补正反例。

自测将文件 URL 转换为文件系统路径，覆盖含中文、空格的工作区以及默认/CI 依赖入口；嵌套子进程必须实际执行断言，不能因测试运行器上下文而全部跳过。

这是源码门禁，不是完整数据流证明。跨文件错误卡包装、动态组件、消息 API 别名或框架特例需要在宿主扩展并补正反向用例；合法的本地校验应保持本地反馈，不以删除校验或伪造请求错误来迎合检查。`duration={0}` 也不能把旧浮动容器伪装成页面内嵌态，必须结合真实布局核查。未改造的存量 App 继续使用原 Trace 审计，不因本脚本新增而强制重构。

## 行为验收

先补失败测试，再实施迁移。使用实际公共包、实际宿主队列和真实页面入口，覆盖清单中本次涉及的路径，确认请求错误只进入根出口且不再进入旧容器。验证 HTTP、业务码和网络错误的 Trace ID 展示/复制、默认三秒关闭、手动关闭、同文案新事件独立计时、重渲染不延时、旧事件不能删除新事件，以及身份切换/卸载后旧回调失效。

真实 Shell 下验证桌面、平板、手机，以及抽屉等 overlay 遮挡场景。页面内嵌错误和权限 inline/page 等待超过 Toast 时长仍可见；同一失败没有重复 Toast；关闭提示不会额外发请求或重放写操作。自动化可以模拟 API 失败，但交付说明须区分模拟页面验收与实际后端联调。原 Trace 静态审计通过、单测通过或依赖升级本身都不代表全入口迁移完成。
