# 选图、口径与建设范围

本文件供已触发的分析任务使用。实例中的客户、回款、工单字段和状态值都须映射到实际 Schema 与业务约定。

## 先形成业务口径

用简短说明记录：问题 → 统计对象与粒度 → 指标／去重方式 → 时间字段、范围及时区 → 状态及权限范围 → 空值／单位 → 放置位置。这是业务决策记录，不是新的配置协议；执行仍使用包现有合同。

“销售额”“回款”“待处理”可能有多种业务含义。先从 PRD 和既有模块查证：已到账记录合计与扣减退款后的净回款不同；订单日期与回款日期不同；待响应与所有未关闭工单不同。无法查证的关键区别需要一个业务问题，而非自行决定。口径已明确时直接实施。

位置已明确则沿用；单图一般嵌入对应业务区域。只有读者需要集中比较多个相关问题时才组合专题页。超出当前问题的其他指标、导航或整套分析模块先保留为可选建议。

## 有边界的数据核对

- 从可读 Schema 字段选维度。直接聚合分组看 `capabilities.aggregable`，不以列表 `groupable` 替代。业务 DateTime 是特例，保持 `aggregable=false`，在同一个 `group` 项中指定 `granularity` 后可作为时间维度。sum/avg 等指标按函数和字段类型判断，不要求指标字段 `aggregable=true`。参见 [Data API 合同](../../makedsl/references/DataAPIDesign.md#聚合统计-record-数据)。
- DateTime 统计优先复用正式分析包0.1.9的 [DateTime 合同](datetime.md)：UI／Service同版，公开校验器和查询均须实际验证。0.1.8及旧版先升级，不因旧限制生成一条宿主专用直查／通用计算链。原本直接使用Data API的场景仍按 [App Service 接入](../../make-app-service/references/make-data-adapter.md#aggregate-statistics) 执行，不据此推断所有旧制品都支持。
- 优先请求本次问题的全局指标和受限分组，核对 `pagination.total`、空分组、日期跨度和实际分类数；样例页或前 N 组不能代替整体分布。
- 严重缺失的分类不默认做业务占比；全零、负值、只有一个时间点或极端数值会改变适合的展示。质量提示来自查证结果，不将某个验证集的异常写成所有项目常驻提示。
- 保留 Lookup 的分组记录 ID，同名标签不合并；Lookup 的过滤值、展示值和分组身份按原合同分别处理。
- Number 没有币种时保留原值，不从“金额”名称推断人民币。Percent 不自动乘 100；单位、精度、原始值和格式化分开处理。
- 未返回日期桶默认留空；补零须为可加原始count／sum且非Percent输入显式声明missing: zero，时间桶须实际覆盖且非未来；类别仅补其他来源已有身份。NULL不当零参加均值，“缺少日期”与“该期间没有记录”分开说明。

## 按问题选固定模板

按业务问题、统计粒度和对照关系选图，再看数据是否符合资格。下表包括基础与专用序列模板；安装制品的公开合同和适用性校验负责最终资格，不由页面再写一套规则。

| 要回答的问题 | 优先展示 | 数据条件和限制 |
| --- | --- | --- |
| 一个明确范围内有多少、合计或平均多少 | 指标卡 | 全局数值指标；指标组用于无维度、至多一行的结果；不把某个分组冒充全量 |
| 随时间如何变化 | 折线图 | 真实日期维度、明确时间粒度及顺序、至少两个有效时间点；不对数字分类轴伪造时间 |
| 同期部门与整体、多个来源如何比较 | 多系列折线／面积，必要时虚线基准 | 来源按实际日期桶对齐，单位和百分比语义相容；部门和整体存在重叠时不能堆叠；使用专用分组序列合同 |
| 不同类别之间谁高谁低 | 柱状／条形图 | 分类维度与数值指标，长度和分类数在包支持范围内；长名称排行优先横向条形图 |
| 同类别下几个指标或系列谁高谁低 | 分组柱 | 类别身份和单位一致，系列数量受控；多来源先对齐，不按显示名称拼接 |
| 整体由哪些部分组成 | 饼／环图 | 完整、少量互斥类别，可加的非负指标且总量为正；当前基础模板通常适合 2–6 类，Top N／部分结果不表示整体占比 |
| 每期总量的组成如何变化 | 受控堆叠柱 | 宿主证明组成互斥可加；当前序列模板不堆叠负数、百分比、均值或去重数；缺组成不补零 |
| 前几名是谁 | 排行条形图 | 明确指标、降序和 Top N，说明它是部分排名；不能将其饼图解释为整体份额 |
| 同时观察数量与金额 | 柱线组合 | 一个聚合结果中的明确指标，最多双轴；单位不同分轴，说明两个轴，不为了装饰默认双轴 |
| 实际距离目标多少 | AnalysisTargetView实际／目标／差额／完成率／进度；需要时配合combo | 宿主提供组织、期间、版本、单位与唯一匹配；0.1.7仅支持越高越好、非负实际及正目标，不伪造目标 |
| 最近几期与累计如何变化 | 累计或连续窗口曲线 | 使用0.1.7 transforms，保留起点、跨年重置及窗口不足原因；月均不冒充记录加权均值 |
| 哪些部门同比增长最快 | 派生排名条形图 | 两期全部可见部门先取全、按原ID算增速再排名，不先取金额前十 |
| 各组成占比如何变化 | 百分比堆叠 | 互斥可加，分母仅所选组成；NULL、零合计和溢出保留原因 |
| 两个数值在各分组有什么关系 | 散点 | 一个分组、两个数值、完整结果；保留身份和两个单位，不推断因果 |
| 月份与类别的交叉分布如何 | 二维热力 | 恰好两个维度、一个数值、完整结果；NULL／缺失留白，保留真实零值 |
| 字段是否齐全、样本能否解释指标 | 样本／缺失率卡与说明 | 非空不等于业务有效；按 dataQuality 模板处理，不把零、负值都当作缺失 |
| 需要精确值或当前形态不适合已选图形 | 汇总表 | 保留同一查询结果、覆盖范围、单位与分组身份；不隐藏失败或伪造替代数据 |

开发阶段可用 `recommendViews` 辅助判断，用 `resolveFixedPresentation` 验证已经选定的 `views`。交付使用固定模式；数据变化使模板失效时交由包回退结果表，不根据偶然返回重新选业务问题或图形。

面积、分组柱、堆叠与跨来源逐组派生使用 [分组序列](grouped-series.md) 的 `SeriesChartSpec`，不在基础 `definition.views.kind` 中填写 `area/stackedBar`。包的推荐是结构规则，不证明业务指标有意义；Agent 负责建设时规划，包负责运行时合法性与回退。

0.1.7散点／热力通过[独立映射合同](release-017.md#散点与二维热力)接入，不由旧自动推荐启用。漏斗、层级、地图等仍须核对数据、公开模型和交互能力，不透传ECharts option绕开合同。状态快照不表示流程漏斗，金额序列不天然支持预测。

## 复杂指标保留真实口径

优先下推后端可表达的聚合。一个聚合不能直接表达时，沿用 [Service 聚合指导](../../make-app-service/references/make-data-adapter.md#aggregate-statistics) 和 [等价查询／结果组合方案](../../makedsl/references/DataAPIDesign.md#不能直接表达时的方案选择)：可以在 Service 对少量同口径汇总做精确组合，或在必要、范围合理时读取所需明细计算。不要因单接口缺少一个函数就认定业务完全不可实现，也不默认下载全部数据到浏览器。

全局均值优先由后端 avg 给出，不能平均各组平均数；去重数在集合可能重叠时不能相加。跨对象金额相减需核对关联、去重、币种和退款等口径。平均解决时长需逐条时差数据，不能用日期均值相减代替。比较、比例和同比环比还要核对分母、周期、零分母和 NULL 规则。

已有派生指标使用 `DashboardResult`，逐组计算使用 `GroupedSeriesResult`，不硬塞为另一实体的 `AnalysisResult`。这些公开合同仍不能表达时，由 Service 给出明确业务合同或评估包的扩展点；如果涉及新增字段、专用接口、近似或统计表，说明具体影响和维护成本，再按用户授权的范围推进。
