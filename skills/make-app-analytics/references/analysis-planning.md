# 分析规划与渐进建设

多指标或页面级需求读取本文件。单张卡或图可在现有需求记录中写清必要口径，不额外创建分析规划平台或新的配置协议。

## 从初始化到追加需求

| 项目状态与用户意图 | 实施范围 |
| --- | --- |
| 初始化只要求业务录入、查询、审批 | 完成原业务；不做分析访谈、统计探查、包安装或导航占位 |
| 初始化 PRD 已要求分析 | 将已提出的分析与原业务一起规划；不扩展到所有对象 |
| 已有列表需要一个汇总指标或一张图 | 嵌入该业务区域；按已确认范围及授权接入，需要跟随列表时先核对全部已应用筛选能否等价映射；需要新聚合的指标才进入分析链路 |
| 明确提出专题分析页或经营驾驶舱 | 围绕使用者的判断任务组合多个区块；分别说明时间及范围，避免强行给所有对象套同一日期 |

用户说“工作台”时，先辨别业务入口、待办和经营概览；业务入口不自动增加统计。用户说“报表”时，先辨别明细打印／导出与分析，不单靠词语路由。已明确的分析需求直接推进，不再次询问是否启用。

## 先确定要帮助用户判断什么

从 PRD、既有功能和已确认规则提取读者与目的，再整理本次需要的指标。常见问题包括规模、变化、结构、效率、目标和质量；按需求选择，不要求每页凑齐六类。

在宿主现有需求／设计记录中形成下列简表；业务决策留在宿主，运行时仍使用包现有的注册与展示合同：

| 项目 | 记录内容 |
| --- | --- |
| 使用者与问题 | 谁使用、要比较或判断什么；哪些内容不在本次范围 |
| 指标与粒度 | 对象、实际字段、聚合函数、记录／人员／客户等去重身份；标签与业务含义 |
| 统计范围 | 授权范围、基础条件、包含／排除状态、时间字段、左闭右开期间及时区 |
| 派生关系 | 分子分母、共同群体、比较基期、单位；目标或基准的可信来源 |
| 查询方案 | 单对象聚合、多个汇总组合、分组序列，或确有必要的受限明细计算；唯一来源、复用关系、预计分页和调用预算 |
| 固定展示 | 图表类型、系列、位置、筛选；选择原因及不适用时的处理 |
| 解释和验收 | 公式、实际范围、单位精度、完整性、NULL／零分母；独立核对依据 |

对象较多不代表每个对象都需要图表。优先使用已有字段和可表达的聚合；需要新字段、历史快照、统计表或专用接口时，说明维护成本和依赖，不悄悄扩充本次业务范围。

## 什么时候询问用户

- 先查 PRD、业务规则、Service、实际字段与状态值。已确认规则直接复用，不重复访谈。
- 只有会改变结果的歧义才询问，例如“销售额”是下单、确认还是完成金额，“完成率”的分母是哪批记录，“月学习率”使用哪个月的应学习人数，以及目标从哪里取得。
- 对“做一个销售概览”等较宽请求，先给出与已知业务有关的少量候选指标及缺失口径，合并关键问题；不要让用户从空白清单选择全部指标。
- 日期分桶、常规图形、组件、列宽和颜色沿用核验后的包能力与宿主规范，由 Agent 决定，不要求用户完成技术问卷。
- 初始化尚无记录时，按已确认业务定义和真实 Schema 设计固定视图，并显示空态。合成数据仅放用户要求的演示／测试环境，不伪装为真实统计。

## 页面内容与视觉组织

先交付最小可用区块，再按用户后续问题增加指标。概览可先放核心规模卡，再放趋势及必要对照，然后放结构／排名；精确汇总通常放在对应图表的明细中。只有问题需要时才增加效率、目标或质量区域，不把这些顺序写成所有行业的固定模板。

筛选应说明影响哪些区块；档案总量、期间订单和历史人员快照可能使用不同时间语义，不能只为共用一个控件就改变口径。参考值、目标和同期值必须有明确来源，不由 Agent 从样本推断。

列表联动按 [筛选交接](list-filter-integration.md) 核对实际能力；无法完整表达关键词、多选或复杂条件时停止该联动统计并说明限制，不能以范围标签相同代替真实条件相同。

图表与卡片标题使用业务名称，统计解释放问号并按条换行。业务外边距、路由、页签与响应式编排交给宿主；内容布局和结果格式复用公共包。数据明细与主图消费同一份结果。当前活动区块按需查询，切换筛选或授权后清除旧结果和旧明细。

按 [图表占位与布局](chart-layout.md) 为本次视图确定位置和可读空间，避免所有图区机械二等分、指标卡随高图拉伸，以及少量数据的大空框。将宿主编排与包内部绘图区问题分开；缺少公开尺寸能力时说明依赖，不靠私有样式补丁伪装完成。

这份规划指导实施阶段选图；运行阶段展示固定配置，由包执行资格检查和安全回退。不得把默认选图改成让业务用户在页面上选择引擎或图形。

页面布局确认后，按 [请求与大数据验收](query-performance.md) 检查初始化、目录、聚合与明细的拥有者。同范围指标合并，图形复用结果；不能为了一个图先加载全 App，也不能仅提高并发和超时来掩盖重复调用。
