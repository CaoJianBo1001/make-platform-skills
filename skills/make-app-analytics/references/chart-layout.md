# 图表占位与页面编排

在确定固定视图后、编写宿主布局前读取本文件；已有分析页出现图形过小、大块空白、错位或隐藏后恢复异常时也读取。选图仍按业务问题及资格规则，不为填满页面改变指标或数据。

## 先分清哪一层产生留白

| 观察结果 | 拥有者与处理 |
| --- | --- |
| 标题、页签和图表共同缩在工作区中央，外侧空白很宽 | 宿主复用既有页面密度，检查最大宽度、重复 padding 和壳层内容区；沿用主题间距，不新增一套 token |
| 指标末行孤立一张，或单图右侧留出半页，即使没有空节点 | 宿主检查实际卡数、grid 轨道、跨列及子项最大宽度；删除空节点不等于清除了空轨道，需重排现有内容 |
| 同排图表底边错位，或只拉长外框而内容仍堆在上方 | 宿主协调本行高度与公开图形尺寸，同排同层级卡片上下边缘对齐，有元信息页脚时页脚底缘对齐；紧凑指标与大图分区，不将所有行固定为同一高度 |
| 卡片边界合理，画布却很小，坐标轴、图例占据大部分空间 | 分析包检查图形模板内部 grid、轴标签、图例和半径；宿主通过公开端口配置，缺少端口时反馈包能力缺口 |
| 页签重新出现、侧栏收起或容器变宽后图形尺寸不更新 | 宿主先核对真实容器尺寸与可见性；包负责引擎的尺寸观察、resize 和实例清理，不在宿主另起 ECharts 实例 |

包组件的私有选择器、内部 ECharts option 和分析 Definition 都不是页面布局协议。不得给没有声明的组件添加 `height`／`option` props，不把 span、padding 或任意引擎配置塞进严格定义。

## 同排对齐与高度分配

- 桌面同排、同层级的图表卡片默认外框等高、上下边缘对齐；核心指标在同一组并排展示时也对齐外框。每一排按自身内容确定合理高度，不把整个页面的全部卡片固定成同一高度，也不把紧凑指标与大图强行混成一排。
- 分开处理外框与内部：仅设置网格 stretch 或卡片高度不能证明完成。图区通过已核验的公开布局／高度端口分配本行剩余空间，页脚保留在底部，不用大块 padding 或空节点填洞；不拉伸图形比例、不增加业务内容。没有页脚的组件不编造元信息来凑齐。
- 宿主使用尺寸观察协调时，只测量自己拥有的容器边界，按实际换行分组，批量读取后再更新公开尺寸。复测须恢复自然高度，避免把上次补齐量累计进来；同帧通知合并，退出时清理观察器和待执行帧，不改写引擎实例或查询数据。
- 筛选、标签换行、图例数量、字体加载、侧栏及容器宽度变化后重新协调；手机单列或重新分行后清除上一排的补齐量，回到自然高度。短表回退可单独占行，不能继续保留大图补齐量。
- 如果合理图高仍无法兼顾同排对齐与密度，调整区块组合或分行，再验收阅读顺序；不能把“不强制全页等高”理解为同排任意错位。公开尺寸端口不足时说明具体包侧缺口，不能覆盖包的私有内容结构。

## 根据内容安排占位

先判断每张图需要的最小可读空间，再决定并排、跨列或独占一行。按宿主实际内容区宽度重排，不以屏幕宽度直接推断卡片宽度。多图不必全部二等分；少一张图时不保留空的网格项，也不使用任意补图填洞。

| 内容 | 推荐的布局判断 | 常见问题 |
| --- | --- | --- |
| 核心指标与派生指标 | 优先紧凑指标组，按标题和数值长度换列；换行后的首列与上一行对齐 | 把单个数值放进整张趋势图高度的面板，或为填一行重复指标 |
| 折线、面积、多系列趋势 | 给时间轴足够宽度；系列多或需要比较细节时跨列，窄屏上下排列；高度留给趋势辨识和图例 | 手机仍并排两图；只有一桶时保留空画布，或造点补齐折线 |
| 分类柱、分组柱、堆叠柱 | 宽度容纳实际分类与系列；标签过密先调整布局或使用已支持的受控展示方式 | 为塞入窄卡而省略全部标签；以截断结果冒充完整分组 |
| 横向条形与排名 | 高度随实际展示行数和标签可读性确定；少量分类用紧凑区域，多行才增加高度或受控局部滚动 | 两三条数据撑出巨幅空白；长名称占用过宽轴区或被截断后无法查看 |
| 饼／环图 | 少量合法分类使用适度宽度，按容器宽度安排图例与引导线；与趋势并排前检查两图的有效绘图区 | 单个环图占满宽屏整行；图例挤成多行后圆环缩成小点 |
| 精确结果表、回退与明细 | 宽度按维度和数值列需求分配；短表随内容收缩，长表在所属容器内滚动；汇总明细从原图打开，按统一容器展示 | 为表格回退保留原图大高度，或把弹层明细改成行内展开而拉高相邻卡片 |

### 按实际数量重排，检查整组占位

- 指标组同时考虑实际卡数和最小可读宽度，不能只由 `auto-fit` 或固定列数决定。末行孤立或明显空缺时，可减少列数、按行分配剩余卡片或跨列；例如最多四列时，五张可排三加二、六张可排三加三，前提是标签和数值可读。示例不规定通用列数，也不要求独立单指标撑满宽屏。
- 图表行按当前实际展示项决定轨道和跨列。只有一张图，或宽图使剩余紧凑图单独成行时，重新组合已有区块；不保留无内容的半行轨道。子项自身限宽也可能让两个相邻网格项之间出现大空隙，须检查可见卡片边界，而非只看 grid 的 gap。
- 需要适度宽度的单张环图，可与本次已有且语义相关的指标／派生指标组合，并按阅读顺序在手机堆叠；也可采用合理限宽的独立区块。比较整组左右区域的内容高度，避免一侧结束后另一侧仍延伸很长、留下大片背景。不要靠放大圆环、拉高数值卡、搬入无关内容或追加查询填满区域。
- 宽度增加可能使指标多出一列、减少一行，反而破坏左右区块平衡；最大列数是上限，不是必须达到的目标。嵌套布局分别以所属工作区和指标组的真实宽度决策。使用 CSS 容器查询时核对最近祖先的匹配关系，需要区分容器时使用命名查询或等效的明确尺寸来源，避免内层容器误接外层断点。

单日期桶等不满足图形资格的结果采用包的可信回退，未返回期间默认不补零；显式补零须满足[0.1.7输入规则](release-017.md)。增加空间不能解决资格问题。环图、轴刻度及标签保留必要留边，不截断数轴制造变化，也不拉伸图形。

主动打开的汇总明细按 [默认容器](integration-contract.md#汇总明细的默认容器) 使用 PC 居中弹窗／手机底部弹层，不因表格宽或行数多随意改成右侧抽屉。图形资格失效后在原区块展示的结果表仍是回退内容，不强制自动弹窗。

## ECharts 尺寸与生命周期

- 分开检查卡片、图形容器和有效绘图区。先排除宿主多层空容器、固定行高、`min-height` 和过量内边距，再判断是否是包内部 grid、legend 或轴标签留边过大。不要用缩小整个卡片去掩盖模板内部比例错误。
- 宿主外层 grid／flex 子项允许合理收缩，例如在自己的布局节点使用 `min-width: 0`；需要局部滚动的 flex 区域建立有效高度链及 `min-height: 0`。`height: 100%` 必须有确定的父级高度，不能把它当作自动测量内容。
- 图形高度按类型、实际可用宽度、分类数和图例量选择，遵守宿主已有密度；不要统一给所有卡片大固定高度、整屏高度或同一宽高比。布局在加载前可预留合理稳定空间，结果为短表或紧凑卡片时应按实际内容收敛，避免常驻大空框。
- 仅使用实际制品公开并核验的尺寸 props、主题或 CSS 变量；同时验证手机断点是否覆盖该配置。未开放对应能力时记录包侧缺口，不能覆盖私有 CSS、手改依赖或声称已实现自动高度。组件内部的空态／错误态最小高度问题也按包缺陷处理。
- 宿主保证活动图形在可见、有实际宽高的容器内展示；隐藏页签不参与占位。恢复可见、侧栏展开／收起和窗口改变时核对尺寸更新。引擎观察器、resize、事件解绑及 dispose 复用包现有生命周期；不要靠反复初始化或伪造全局 resize 事件补救。
- 尺寸、视觉主题和明细开关变化只影响展示，不重新请求统计；渲染使用同一可信结果。数据变化引起的重新绘制也不能绕开原查询控制器。

## 交付前检查

对本次实际选用的图形按 [数量与宽度交叉验收](acceptance.md#布局数量与宽度的交叉验收) 检查手机、常见桌面、应用允许的最宽内容区，以及列数变化前后；增宽和缩窄都要验证。再覆盖侧栏切换、页签隐藏后恢复、筛选后少量数据及长标签／多系列。无需为一次单图需求实现全部图形。

检查四个边界：页面工作区、卡片外框、图形容器、实际绘图区。记录造成留白的具体层级；截图之外检查真实宽高、溢出与可见状态。同排卡片核对顶部和底部边缘，有页脚时核对页脚底缘；不能只检查标题。指标换行不偏移，图例、轴标签和单位可读，无大块无用途空框；无整页横向滚动，必要表格滚动局限在所属区域。

逐排检查实际首尾边界、可见卡片间隔和末行剩余空间，再看整组左右区块是否失衡。先补能复现问题的宿主布局回归，再修改布局；纯函数或样式断言不能证明上述浏览器几何结果。保留必要阅读留白，不以统一像素、填满率或所有卡片铺满整页作为跨 App 标准。

加载到成功、空数据、错误及图形回退后，既不突然塌陷遮挡后续内容，也不永久保留无用的大图高度。明细关闭后不留行占位，Tooltip 可查看完整省略文字。调用次数保持原预算。

规则修订、包内部能力实现和真实页面验收分别记录。只修改 Skill 不能宣称某个宿主或所有图形的留白已经修复；需要包扩展时，列出缺少的公开能力及对应浏览器回归，再按任务范围实施。
