# 公共组件语义主题接入

## 适用范围与发布边界

本指导用于已明确纳入公共组件主题同步的项目。默认宿主接入仍按 [组件与主题](component-usage.md#完整方案应用与差异记录) 执行，不因选择 MakeDesign 自动改包。

`makeui-public-theme/v1` 归一与适配资产已与正式 `@qfei-design/canvas-table@1.3.5`、`@qfei-design/make-app-approval@0.2.17` 核验。两包的 registry 元数据、tarball SHA512 integrity、公开导出／类型、运行代码和样式均须对应实际安装版本；语义主题常量分别为 `canvas-table/semantic-theme/v1` 与 `make-app-approval/semantic-theme/v1`。包内仍可能残留 unpublished-candidate 等旧文案，不能单凭该文案否定已发布能力，也不能只看版本号或伪造常量跳过门禁。

明确进行新主题接入时采用上述正式基线，同一宿主中审批列表与独立 Canvas 使用同一份 Canvas 依赖和主题来源；审批包的宽 peer 范围不代表旧 Canvas 已支持本合同。未要求升级的既有项目保留锁版与原公开 API，缺少语义主题时显式使用旧版兼容路径并记录差异，不传不存在的参数、不覆盖私有 CSS。后续使用候选隔离验收仍须记录源码、构建 integrity 与入口，候选路径不得进入正式依赖。

## 一次接入，按数据更新

MakeDesign 交付视觉与布局数据；makeui 在宿主适配层将其转换成稳定语义主题；公共包只接收自身公开主题 API，不读取方案 URL、风格 ID、官网或 Skill 路径。保留所选完整主组件库，不为主题适配另装 AntD。

```text
项目固定方案快照
  → makeui 的唯一归一层 makeui-public-theme/v1
  → 所选主组件库、Canvas、审批的公开适配
  → PC 各区域与独立弹层
  → 手机仅品牌／选中强调色投影
```

颜色、字号角色、密度、间距、圆角、边框和阴影按语义映射，不按 `linear`、`notion` 等风格 ID 写分支，不在各包复制调色板。公共组件只消费其实际支持的语义；页面／抽屉／弹窗选择、导航、区域组合与宿主内边距仍由宿主布局负责，不能变成公共包业务状态机。

| 变化 | 更新位置 | 是否需要改组件包或 Skill |
| --- | --- | --- |
| 同一合同下更换已支持的颜色、字号或间距值 | 项目方案快照 | 不需要 |
| 更换已支持的导航／详情容器选择 | 项目快照及宿主公开布局解析 | 不需要逐包修改；保留 Make 容器边界 |
| 新增已有语义到另一公共包的公开适配 | 唯一适配层和该包接入指导 | 只改受影响接入，不复制映射 |
| 新增语义能力或不兼容协议 | 合同、受影响包公开 API 和接入指导 | 需要一次能力升级和回归 |

随包参考实现位于 [public-theme 资产](../assets/public-theme/README.md)。AntD 桥接复用既有纯解析器；其他组件库须提供其真实语义基线及方案解析，不偷偷套用 AntD 的默认值。页面布局继续读取 [页面设计基线](page-design-quality.md) 与 [Shell](app-shell-layout.md)。

## 固定快照与主动更新

项目保存原方案 URL、交接合同、选择数据、解析后的设计数据、来源版本／hash、主组件库版本和适配合同版本。原 URL 供追溯，不作为运行时自动拉取指令。应用加载时使用已固定快照，不轮询官网、不自动跟随官网默认主题；网站后续修改不能直接改变已有项目。

项目明确更新方案时，重新读取与校验交接，比较变化与能力差异，再替换这一份不可变快照。已有 token 的值变化只流入现有适配器，不重新生成业务代码或逐包修改。新增但未支持的语义须说明影响，不能悄悄丢弃或声称已应用。

热更新不以方案 ID／hash 为 React `key`，不销毁 Controller、Form、路由、选择器或表格。主题数据不作为查询／权限／Schema 的刷新条件。更新前后的输入、意见草稿、已选值、页签、记录选择、滚动和进行中的请求分别验证。

## PC 与手机的边界

PC／平板消费选中方案的完整视觉语义，并按字号角色区分页面标题、记录标题、字段、控件和辅助文字。表单字段、普通详情及新建／编辑仍遵循 [统一骨架](drawer-layout.md)、[字段类型与受控合同](component-usage.md#host-form-controlled-field-contract) 和权限字段集；视觉更新不改变 Make 值、动作资格或保存语义。

手机严格复用 [手机颜色接入](mobile-theme.md) 的既有八项品牌颜色投影。不得把 PC 的字体、字号、密度、表面背景、边距、圆角、阴影或布局灌入移动 Provider。输入、数字、下拉、日期、人员、部门、Lookup、附件继续使用原移动专用控件；全屏任务页、同排标签／值槽、右对齐、底栏与更多操作沿原移动规范。本批不修改移动 npm 包。

## 公共包能力与后续顺序

| 区域 | 本批接入方式 | 保留边界 |
| --- | --- | --- |
| 主 UI 库和宿主表单／详情 | 既有公开主题与 makeui 资产 | 不复制第二套字段行为 |
| Canvas | 正式 1.3.5 的公开 `ITableStyle` 和原 `updateProps({style})` | 绘制、缓存和 tooltip 由包负责；不重建表格 |
| 审批 | 正式 0.2.17 的语义主题及 `/react` Provider／插槽 | 状态机、授权、提交与字段来源不变 |
| 手机 | 既有公开颜色接口 | 仅品牌色，原移动显示合同不变 |
| 筛选／分组／排序／操作 | 后续按各包公开适配接入 | 本批未修改，不宣称完整同步 |
| 分析／AI／通知／打印 | 后续由各自 Skill 核验公开能力 | 图形序列语义、通知层级和打印输出独立验收 |

Canvas 和 DOM 对颜色的能力不同。纯适配器不能把尚未解析的 `var()`、`color-mix()` 或 `currentColor` 直接交给 Canvas；通过受控的宿主颜色解析边界得到可绘制值，无法解析时返回明确缺口。不能静默变黑、使用上一份颜色或伪造所有值均已生效。

PC 审批列表的内部 Canvas 也使用同一宿主 resolver，由 `toApprovalTheme` 的可选 `resolveColor` 统一处理颜色／边框；受控 Host 自动转发，不在宿主或各包再写风格色值分支。注入的控件仍是所选主组件库的完整组件，由其公开 Provider／props 消费同份主题；包不能对 `renderField` 内所有 input／textarea 后代强加几何或覆盖私有输入节点。手机保持独立颜色 Provider，不继承 PC 的组件库配置。

主题必须传到实际绘制面：Canvas 重绘与文字缓存、表头／汇总／空态／滚动条／tooltip，审批列表／详情／意见／状态，以及宿主 Portal。两个不同主题区域互不污染；Portal 脱离 CSS 祖先时经公开插槽显式传入样式或上下文。宿主自定义 Canvas renderer 也读取同一主题，不能继续闭包缓存旧色。业务行色的优先级保持原公开合同。

## 交付验证

1. 默认主题、两个不同方案及任意一组颜色／字号／间距值，全部走同一合同和同一套代码；比较实际绘制及计算样式，不只比对象。
2. 同页双主题、跨入口、独立 Portal 和热更新均正确；未提供主题时与发布基线一致。Canvas 验证文字、网格、表头、汇总、选中／活动、分组、空态和 tooltip。
3. 保留表格选择、滚动、编辑会话；审批意见、字段值、校验、只读和任务动作不变。更新主题不增加业务请求或提交。
4. 手机切换方案前后仅品牌色变化，控件、布局、字号、密度、触控和交互保持冻结规范；保留 PC／手机同一业务 Controller。
5. 实际正式依赖及公开类型通过；旧正式包走原兼容路径，新能力不能因常量缺失被伪造。源码／类型／组件测试、真实浏览器和真实设备验收分开报告；审批三终态禁编与已完成任务只读仍保留各自宿主适配，不能因主题接口发布而删除。

没有公开支持的选项按 [能力差异](component-usage.md#完整方案应用与差异记录) 记录，不补私有选择器，不以全局覆盖实现“统一样式”。
