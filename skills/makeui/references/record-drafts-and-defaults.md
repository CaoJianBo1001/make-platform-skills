# 按需草稿与字段默认值的表单交互

## 只在用户需要时启用草稿

用户未要求草稿时，不添加“保存草稿”、状态字段或草稿功能选项。字段默认值可独立接入。持久化业务草稿不同于输入中的本地暂存；数据、权限及写入协议由 [Service 业务草稿合同](../../make-app-service/references/business-record-drafts.md) 主责。

明确需要草稿时，保存动作统一遵循 [表单保存意图矩阵](mobile-form-controls.md#表单保存意图矩阵)；动作资格和业务含义由同一 Controller 提供，桌面/平板沿用头部，手机按矩阵组合一个保存区。不维护第二套动作数量或组件兜底。检查窄屏排列、触控和关闭入口，不能仅因桌面视口变窄或发生错误就放大所有按钮。

| 意图 | 表单校验 | 提交 |
| --- | --- | --- |
| 保存草稿 | 允许必填缺失；非空输入的类型/日期/选项/范围等校验保留 | Service 查询参数 `isDraft=true`；由 Service 同次生成草稿状态 |
| 保存 | 完整必填及业务校验 | 省略或 `isDraft=false`；Service 同次生成正常保存状态 |
| 保存并提交 | 完整校验及原审批准备 | 原 Workflow 编排，正常保存状态；不向 Workflow 加 `isDraft` |

项目保存状态字段在新建、普通编辑和 BPM START 表单均不注册为输入，仅从有权限的列表、手机卡片和详情只读展示。单元格、批量字段菜单不得提供它。状态字段不改变审批系统状态和权限；隐藏输入仍须由 Service 校验生成字段的写入资格。

## 失败后继续修改

提交期间互斥防连点；结束后根据可靠写入结果恢复。普通保存明确未落库的校验/业务拒绝，结束 pending，保留输入、选择项、原记录 ID 及已确认上传结果，允许修正后再次保存。HTTP 200 仍可能是业务失败，使用已确认的操作/错误合同判断，不能仅靠 HTTP 状态或文案猜测。

网络中断、超时、响应缺 ID 或写入结果未知时，保留原有防重复创建保护并解释状态，沿用既有核查/恢复方式，不盲目解锁重发。新建“保存并提交”可能先落库后发起失败，不能把所有非成功业务码都视为未创建；见 [审批保存会话](../../make-app-approval/references/initiation-contract.md#保存与首次发起)。真正的权限收回、锁定或流程禁编仍保持只读，普通输入错误不应永久禁用整张表单。

## 新建表单使用固定默认值

从当前场景权威元数据读取字段顶层 `defaultValue`，保持类型、有效选项及权限。普通新建使用 `createFields`；审批新建使用 START 字段定义及其授权，不以普通 Schema 补授权。若节点接口未返回默认值，报告缺口或依赖已核实的后端补齐，不从可见 fields 或本地 DSL 猜值。

只对全新记录、当前允许创建/编辑且未出现 key 的字段预填。用 key 是否存在判断，不能用 `value || defaultValue` 或空值合并覆盖显式 `null`、空串、空数组、0、false。数组/对象按记录深拷贝；人员/部门按 ID 格式接入已授权候选/展示层，不用显示名写入。

数值字段的最终 JSON 必须保留输入意图；保存、保存草稿、保存并提交都检查实际序列化后发出的请求体，不能只检查内存表单值或 mock API 函数参数：

| 数值字段的输入意图 | 最终 data 示例 |
| --- | --- |
| 表单未产生该字段 key | `{}`，省略 key，由已核实的创建默认值合同处理 |
| 用户明确清空 | `{"quantity":null}`，保留显式 null，再按本次请求的必填规则校验 |
| 用户输入 0 | `{"quantity":0}`，保留 JSON 数字 0 |

表单已有预填默认值时，该 key 已存在，不能仅因用户未触碰而删除。`JSON.stringify({quantity: undefined})` 会得到 `{}`；清空后若仍提交 undefined，服务端可能重新补默认值。沿用宿主状态或字段存在性记录区分未提供和主动清空，不以真假、dirty 或空值合并猜测。文本、多选、附件分别沿用原合同的空串/数组等格式，不统一改成 null。可用 [宿主验收工具](../../make-app-service/references/draft-host-verification.md) 通过真实控制器及最终请求边界验证。

默认值初始化仅一次。Schema 刷新、权限刷新、异步选项加载、重渲染、提交失败及用户主动清空不得重新覆盖用户输入；编辑或重新打开已有草稿回显实际记录，不给缺失/空字段重新灌默认值。权限变化清理失效值仍沿用原规则。

平台在创建时统一补齐缺 key 的默认值，前端预填只是交互；历史读取、编辑和统计不补默认值。完整格式及支持类型见 [字段默认值](../../makedsl/references/FieldDesign.md#字段默认值--default-value)。默认值无权、非法或元数据未生效时不代填猜测，不以 UI 预填掩盖后端能力缺口。

验收需分别覆盖无草稿入口、草稿/正常/审批保存、非法非空值、报错后修改重试、未知写入保护、桌面按钮尺寸、手机动作可达、状态只读、默认值显示及主动清空/失败/刷新不覆盖输入。
