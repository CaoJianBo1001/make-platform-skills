# Make App 移动端视觉与交互标准

本规范冻结 Make App 手机端的通用视觉与交互基线，规定后续 Make App 必须复用组件包的默认实现并通过真实页面验证；不得只完成“能响应窄屏”就视为符合标准。这里约束 phone View 和移动 Sheet，不改变 desktop/tablet 的 Drawer、字段控件或表单布局。

安装包的公开 API 存在不等于默认视觉已满足本规范；iOS 搜索输入、缩放手势和附件状态须通过 `mobile-defaults.md` 指向的安装产物校验。不满足时报告组件包依赖阻断，不让宿主覆盖包内部样式来制造表面一致。

## 新建、编辑与详情表单

- 手机任务页的表单容器为白色平面，不加外层边框、圆角卡片或阴影。字段区采用宿主页面留白，不再给每个 Ant Design、Arco 或原生控件套一层输入框卡片。
- 普通字段按一行呈现：左侧标签，右侧值；所有字段值内容靠右对齐，包括输入、数字、日期、选择、人员／部门／Lookup 触发器和只读值。自定义触发器的值与箭头作为整体靠右，值文本本身也靠右。行底只有一条 1px 弱分隔线。输入和选择触发区常态透明、无完整边框、无额外下划线或阴影，触控高度至少 44px。键盘聚焦的 `:focus-visible` 必须保留清晰可见的焦点指示；优先沿用组件包默认样式，宿主自定义控件也须提供等效提示，不得以无边框为由覆盖。焦点指示、校验及弹层打开不能改变字段行高；普通指针聚焦不应额外产生持久盒状边框。
- 只有附件 `File` 使用上方标签、下方内容的上下结构及全宽内容区；长文本、链接、关系和复杂多值字段保留左侧标签槽位，在右侧值槽位靠右展示并随内容换行增高。`TextArea` 默认两行并按内容增长；普通单值字段默认一行。控件自身的增删等操作布局除外。必填标记、错误信息和只读值仍保留宿主表单语义，不可为了视觉对齐删掉。
- 详情页若包含 Tabs／标签页，Tab 栏及选中指示区域与详情正文共用同一左右页面留白，不得全宽贴边；普通详情字段值仍按右侧尾端对齐。
- 表单外观属于 phone View；桌面仍使用原 Drawer 和原字段控件。组件或 CSS 变更必须以 `.make-app-mobile-*` 或宿主 `.mobile-task-page` 等明确的手机作用域隔离。

## 底部 Sheet

- 面板宽度为 `calc(100% - 8px)`，左右各留 4px，顶部圆角 16px，不使用外阴影；底部安全区仍需保留。
- 有“清除”和“确定”的操作栏中，“清除”固定左侧，“确定”固定右侧且保持紧凑按钮宽度；不能把两者都挤到右边或拉伸成等宽按钮。清除操作不可用时只禁用，不移位。
- Sheet 内容滚动区与底部操作栏独立；打开键盘、滚动正文或展示字段错误时不得横向溢出、裁切或被操作栏遮住。

## 日期、时间和范围

- `Date` / `DateTime` 使用底部 Sheet 滚轮：可见区域为五行、每行 48px，当前值处于中线选择带，邻近项逐渐淡出，滚动具备吸附。Date 为年／月／日三列；DateTime 按字段精度使用五列（到分钟）或六列（含秒）。不使用浏览器原生 `select` 或桌面多月弹层代替。
- `Time` 使用与字段精度匹配的时／分或时／分／秒滚轮。编辑现存值、取消或仅确认不得丢失秒、改变时区或提前写入表单；选择完成后只通过一次确认快照更新宿主值。
- `DateRange` 使用单月日历与月份前后切换。日期格为连续七列、至少 44px 触控高度，不画密集格线或格间距；范围中段用轻底色，开始和结束日用主题色圆角强调。边界日禁用，范围未完整时不可确认，取消不写回。
- 显示格式和写入值由字段 Schema 与宿主 API 合同决定。日期组件是受控展示层，宿主负责 schema 值与 `Date` 对象之间的显式适配；禁止把视觉格式化文本当作业务值提交。

## 公共组件与职责

手机端人员／部门与附件优先从 `@qfei-design/make-app-mobile/fields` 使用 `MobileIdentityField`、`MobileAttachmentField`；普通选项和日期从 `@qfei-design/make-app-mobile/pickers` 使用 `MobileOptionPickerSheet`、`MobileDateField` 和 `MobileDateRangeField`，并只在 UI 入口导入一次包样式。`MobileSearchPickerSheet` 是身份字段内部与特殊字段组合可用的底层原语，不是标准人员／部门字段的宿主拼装入口。组件包负责本标准的字段触发器、身份标签与标识、附件卡片、Sheet 几何、选项行、滚轮和范围日历；宿主负责字段 Schema 适配、候选与附件请求、校验、业务值归一化及提交。

- 人员／部门使用 `MobileIdentityField`：单选立即确认；多选以“确定”为唯一提交入口。多选已提交值在新建／编辑触发器内以可换行、右对齐标签展示；人员显示头像或首字回退，部门显示圆形简称。选择 Sheet 顶部已选项可横向滚动且隐藏滚动条，候选勾选不得因内容宽度被推出视口。
- 附件使用 `MobileAttachmentField`：图片缩略图／文件图标、文件名、状态、圆形删除入口、删除确认和全宽虚线上传区属于标准视觉，不允许宿主改为裸文件名列表或通用 Upload 默认列表。包不执行上传、重试、删除或持久化请求。
- 普通 `SingleSelect` 使用无搜索的 `MobileOptionPickerSheet`，选择或清除后立即确认；普通 `MultiSelect` 使用同一组件的多选模式，以“确定”提交草稿。
- Date／DateTime／DateRange 使用对应日期组件。若当前包版本未公开所需组件或属性，不得伪造深层导入；先升级受支持包或报告依赖缺口。
- 新建／编辑底部保存／提交使用 `MobileFormActionBar`，单个按钮无图标、靠右并保留安全区；详情记录操作（编辑、删除）使用 `MobileBottomActionBar`。两种操作栏不能互换。
- 不复制任何试点应用的业务字段、接口、类名或整页源码。确需宿主样式时，限于 schema adapter 或页面组合，并保证窄选择器命名空间、避免全局控件覆盖。

## 实际页面验收

在 390px 和 767px 的真实新建、编辑、详情页面逐项对照本冻结基线：普通输入常态无卡片边框、字段标签与值左右排列、Sheet 左右留白及操作位置正确、日期滚轮有五行中线吸附、范围日历为单月轻网格。使用键盘 Tab 验证交互字段的 `:focus-visible` 焦点指示清晰可见，且不改变行高。保存栏使用无图标、靠右的主按钮。至少验证日期边界、含秒值直接确认和取消、多选草稿确认、单选即时提交，以及返回桌面后 Drawer 和表单不变。升级包后必须重启 Vite 并强制重新预构建，再验证真实页面；静态测试通过不能替代视觉验收。
