# 手机新建、编辑与详情字段适配

## 目标与边界

手机全屏任务页不等于“把桌面 Drawer 放大到 100%”。新建、编辑和详情必须使用同一份授权字段元数据、表单值、校验和提交 Controller，但手机 View 要通过独立字段展示适配层选择适合触控和窄视口的控件。

`@qfei-design/make-app-mobile` 提供任务页头、详情底部操作栏、专用表单提交栏、受控搜索选择器、普通选项选择器、日期/日期时间滚轮、日期范围日历、标准人员／部门字段、标准附件字段和弹层基础设施，不提供完整 Make 字段表单库。宿主继续负责字段注册表、受控表单、候选请求、schema 值适配、值归一化、校验和提交；附件的上传、重试、删除、权限、记录身份和持久化请求也由宿主负责，视觉与文件选择入口使用包组件。所有手机表单与弹层必须遵循 [`mobile-visual-standard.md`](mobile-visual-standard.md)，不得只通过自定义 CSS 临时修正基础组件包的视觉缺口。

## 任务页结构

手机新建／编辑任务页使用纵向 flex 布局：

1. `MobilePageHeader` 固定在任务页顶部。
2. 表单正文是唯一纵向滚动区域，使用一列字段和紧凑内边距。
3. `MobileFormActionBar` 承载保存／提交，固定在正文之后，单个主按钮无图标、靠右展示，并为 safe-area／安全区预留空间；提交中禁用重复操作。`MobileBottomActionBar` 只用于详情记录操作（如编辑、删除），不得用作表单保存栏。
4. 错误摘要位于正文顶部，字段错误紧邻字段，不被底部栏遮挡。

详情任务页使用相同页头和正文滚动边界，但不挂载可编辑表单。详情通过字段 display adapter 渲染紧凑 label/value 标签和值行；不得把禁用 `Input`、`Select`、`DatePicker` 或其他禁用表单控件当成详情展示。

关闭、返回、路由变化和宽度切换必须遵守宿主现有未保存变更保护。桌面 Drawer 与手机任务页不能同时挂载同一个表单实例后用 CSS 隐藏；Controller 可以共享，View 和字段适配器按展示模式单独挂载。

## 表单视觉骨架

- 普通字段使用同一行的左侧标签、右侧值，字段行底部只有一条 1px 主题弱分隔线。
- 除附件 `File` 外，所有表单字段保留左侧标签槽位、右侧值槽位；所有表单字段值内容必须靠右对齐，包括输入、数值、只读值、长文本、链接、日期、范围、选项、人员、部门、Lookup 与自定义触发器。自定义 flex 触发器须把值及其箭头作为整体推到行尾，并让值文本本身右对齐，不能仅把控件放在右侧但文字仍靠左。该规则只作用于手机 View，不改变桌面控件。
- 普通字段的可编辑值区常态无盒状边框；不得增加完整边框、额外下划线或阴影。键盘聚焦的 `:focus-visible` 必须保留清晰可见的焦点指示，优先沿用组件包默认样式；宿主自定义控件提供等效提示，不得覆盖包的焦点样式或统一设置 `outline: none`。聚焦和底部 Sheet 打开时不得改变行高；错误态通过错误文案和主题错误色表达，不破坏行骨架。
- 普通单值控件默认占一行；`TextArea` 从两行高度起步，按内容向下增长，但仍在右侧值槽位。多选值以可换行的内容或标签展示，选值增多时字段行向下撑开，不截断成单行省略号。附件 `File` 因卡片和上传入口需要全宽，使用上方标签、下方内容结构。
- 内边距、字号、分隔色和交互色使用宿主主题 token；不得复制参考实现中的业务颜色或字段名。

对输入控件和只读值直接应用包样式 `.make-app-mobile-form-value`；对 flex 选择／日期触发器应用 `.make-app-mobile-form-value--trigger`，并保证内部值文本自身 `text-align: right`。组件库把真实 input 嵌套在包装器中时，必须对嵌套 input 设右对齐，不能只对外层 `.ant-form-item-control` 或包装器设 `justify-content: flex-end`。选择器候选行和字段标签不右对齐。

## 字段控件决策

手机字段必须继续满足 `component-usage.md` 的 host-form controlled contract：转发 `value/onChange/onBlur/id/disabled`，显示值、校验值和提交值一致。手机适配不得改变 Make 字段值结构或绕过权限字段集。

所有可编辑的原生 `input`／`textarea`（包括文本、数值、金额、百分比和选择弹层的搜索框）在 iOS 上的实际计算字号不得小于 16px；不要只放大 placeholder 或外层容器。标签、只读值和候选行可继续使用设计字号。组件包拥有的输入框应在包内修正，宿主只修自己的输入框，不覆盖包内部 class；安装产物不满足时按 `mobile-defaults.md` 的校验门禁报告 package blocker。保留 viewport 的用户缩放能力，不用 `user-scalable=no` 或 `maximum-scale=1` 掩盖焦点放大；滚动容器若声明 `touch-action`，须包含 `pinch-zoom`（如 `pan-y pinch-zoom`）。

### 文本与数值

- `Text`、`URL`：占满右侧值槽位的受控输入；触控高度至少 44px，不改成跨越标签的全行输入。
- `TextArea`：在右侧值槽位显示，默认两行，按内容自动增长；不得沿用桌面默认四行或强制全宽上下结构。
- `Number`、`Currency`、`Percent`：手机端使用无步幅调节按钮的普通文本输入并设置 `inputMode="decimal"`；桌面可保留数字控件。货币符号紧邻数值文本，符号与数值作为整体靠右，不把符号留在铺满值槽的输入框左侧。沿用共享 raw-text 和精度校验 helper，校验通过后才转成提交数值；符号和分组仅用于显示，不改变提交值。
- 只读或生成字段：使用文本值行，不渲染禁用输入框。

### 日期与时间

手机端不得直接复用 desktop DatePicker、RangePicker、Select 等桌面弹出控件并只修改宽度，也不得把原生日期输入或原生 `select` 作为平台默认。使用包 `/pickers` 公共入口的 `MobileDateField`、`MobileDateRangeField`，并保持 host-form controlled contract；包内默认控件须符合冻结视觉基线，提供 5 行 × 48px 滚轮、居中选择带与渐隐吸附，以及单月范围日历。组件在 Sheet 中维护草稿，点击“确定”后提交一次；取消或关闭不写回。宿主须显式转换 schema 值，不得把组件展示值直接作为 API 值。

- `Date` 使用年／月／日三列滚轮；列值联动，切换年月后把无效日期收敛到当月最后一天。
- 宿主已声明的 `Time` 控件按其时间精度使用时／分或时／分／秒滚轮；不据此发明 `Make.Field.Time` Schema 类型。分钟步长只在 Schema 或业务合同明确时覆盖。
- `DateTime` 按 Schema `format` 和后端精度合同选择滚轮：分钟精度使用年／月／日／时／分五列滚轮；含秒（如 `yyyy-MM-dd HH:mm:ss`）使用年／月／日／时／分／秒六列滚轮。日期与时间组成一个草稿并一次确认提交；不要因手机展示降低值精度。
- 回填已有非零秒值必须原样保留；仅打开后确认、不修改秒，或只修改其他字段时，不得将秒归零、截断或隐式改变时区。取消或关闭不写回。`format` 未声明时沿用宿主统一精度合同；不支持所需精度时报告适配 blocker，不静默降级。
- `DateRange` 使用单月日历 Sheet，提供上一个月和下一个月切换；分别显示开始、结束和区间选中样式。第一次点击设为开始，第二次点击设为结束；第二次选择早于开始时视为反向选择并重置开始。只有开始和结束完整时确认按钮才可用，并提交 `{ begin, end }`。
- `Date`、`DateTime`、`DateRange` 都必须读取 Schema 的 `begin`／`end` 有效边界，禁用越界日期；显示格式与提交格式继续遵循字段 `format` 和后端合同。

人员／部门远程候选默认使用包 `/fields` 入口的 `MobileIdentityField`；它组合了标准字段触发器和 `MobileSearchPickerSheet`。只有超出公共字段 API 的明确特殊定制才直接组合底层搜索 Sheet。普通选项不继承搜索选择器：`SingleSelect` / `MultiSelect` 使用包内 `MobileOptionPickerSheet`；该底层受控组件要求宿主从已提交值初始化 `selectedKeys` 草稿，`onSelectedKeysChange` 只更新草稿，单选即时 `onConfirm`、多选点击“确定”后的 `onConfirm` 才写真实表单，取消或关闭丢弃草稿；交互结束时由宿主字段适配器仅转发一次 `onBlur`，不在草稿回调中触发。不得重新用 AntD `Select` 或宿主原生 `<select>` 实现手机默认选项面板。

如果现有组件只能提供桌面弹层且无法通过公共 API 保证完整边界、焦点和滚动，则这是手机控件适配 blocker；不要用 `overflow: hidden`、缩放整个弹层或负偏移把问题藏起来。

### 候选选择字段

- `SingleSelect` 使用普通选项底部 Sheet，不显示搜索；点击选项或清除后立即提交并关闭，不显示“确定”。
- `MultiSelect` 使用普通选项底部 Sheet，不显示搜索；勾选、删除已选标签和清除只更新草稿，只有“确定”提交完整快照，关闭或取消丢弃草稿。
- 人员 User 和部门 Department 使用 `MobileIdentityField`，候选仍由宿主接口远程搜索：单选立即提交并关闭，多选只在点击“确定”时提交包内当前打开周期的草稿。宿主传入真实 `value`、用于回显的 `selectedItems` 和当前候选 `items`；只在组件 `onChange` 中写真实表单。打开时不得自动聚焦搜索框。
- 人员和部门的编辑触发器遵守同一标准：多选已提交值以可换行标签 tag 展示并整体靠右，不能 `join("、")` 为单行文本或只显示一个省略号；单选显示可读名称并靠右。人员候选与已选项显示头像，头像缺失时显示确定性首字；部门候选与已选项显示统一圆形简称 identity mark。不得在宿主重做这些视觉，也不得遗漏部门标识。
- `MobileIdentityField` 已负责草稿生命周期、顶部横向滚动、勾选标记边界和身份标识。宿主不得覆盖包内部 class 来修补宽度；若公共 API 无法满足需求，报告 package blocker，而不是复制组件或把底层 Sheet 当默认字段。
- `Lookup` 只允许在源记录新建 create 时编辑，并且必须同时具备关系元数据、字段权限、候选读取和写入合同；目标对象真正可搜索时才展示搜索，否则展示无搜索候选列表。
- `Lookup` 即使是单选也必须通过“确定”确认提交快照，关闭或取消不写回；已有记录的编辑 edit 默认只读，直到平台具备原子／条件关系更新合同。不得提供伪造的“新建目标”入口，也不得降级为文本输入。

### 附件

- `File` 在新建阶段仍遵循 record identity 合同：需要已保存记录 ID 才能上传时，新建页不渲染上传控件。
- 编辑页默认使用包 `/fields` 入口的 `MobileAttachmentField`：每个附件显示图片缩略图或文件图标、文件名；未提供 `status` 时不显示状态标记，`pending` 且未提供 `statusText` 时显示带“待上传”提示的时钟图标，上传中和成功显示状态文字。失败且提供 `onRetry`、字段可操作时显示可点击的刷新图标，没有可用重试回调时显示“上传失败”。包提供紧凑的圆形删除入口与删除确认，并在列表下方显示全宽虚线“点击上传”区域。上传、重试、删除、权限、记录身份和持久化由宿主负责；包只把用户选择的 `File[]` 和操作项回调给宿主。遵守 `maxCount`，不把浏览器 `File`、`blob:` 或 `data:` 值直接提交。
- 宿主必须把请求进度与结果映射回受控 `items`；已保存附件不要无依据地映射为 `pending`，应按实际状态传 `success` 或省略 `status`。失败重试通过 `onRetry` 执行并更新受控状态。不得用原生文件名列表、AntD `Upload` 默认列表或临时按钮替代标准附件卡片。删除只有在包内确认后才执行宿主回调。
- 详情页展示文件名、缩略图或下载入口，不展示禁用 Upload。

## 弹层与视口安全

- 优先使用手机底部抽屉、全屏选择页或系统原生选择器；不要在 390px／767px 窄视口中打开桌面宽度的多列日历、长下拉或级联弹层。
- 必须使用组件库 popup 时，通过其公开 portal/overlay API 挂到任务页拥有的 overlay root，宽度和位置限制在 `100dvw` 与任务正文内边距之内，并同时验证 visual viewport（软键盘出现后的可见区域）。
- 弹层不得被任务正文 `overflow` 裁切，不得横向推动页面；正文滚动、弹层滚动和底层锁定各自独立。
- 打开候选抽屉不自动聚焦搜索框；用户主动点击才唤起键盘。普通文本字段仍按用户点击正常聚焦。

## 详情展示

- 手机详情使用单列 label/value 行：除附件外，每行保留左侧标签槽位，值位于右侧槽位并尾端对齐；每行底部一条主题弱分隔线。值和多选项允许换行并撑开行高，通过字段 display adapter 格式化。
- 若详情包含 Tabs／标签页，Tab 栏及其选中指示区域必须与详情正文共用同一左右页面留白，不得全宽贴边；切换标签不得重置详情路由或当前记录上下文。
- 日期和范围显示格式化文本；人员、部门、选项、Lookup 和文件显示人类可读标签，不显示原始对象、数组或 JSON。
- `Lookup` 的展示容器必须使用可收缩 flex，并显式在行尾 end 对齐；长标签不能把值推出视口。
- 只有附件内容可占完整宽度；长文本、链接和关系值留在右侧值槽位内换行。空值显示 `-`。
- 不复制桌面 `Descriptions` 的固定列宽，也不把编辑表单切成 disabled 状态冒充详情。

## 验证与交付门禁

在真实业务页面同时打开新建、编辑、详情，并以 390px、767px 检查：

- 除附件外，表单与详情每类实际字段均保留左侧标签槽位，值在右侧尾端对齐；长文本和多选在右侧槽位换行增高，不因内容增加而改成上下结构或截断。附件保持全宽上下结构。
- `TextArea` 初始为两行，输入更多内容后自动增长；`Number`、`Currency`、`Percent` 在手机端无步幅按钮，输入超过 Schema 小数位数时显示字段错误且不发保存请求，桌面原数字控件不受影响。
- 每种实际出现的字段控件都可完成输入、清除、校验和提交／展示。
- 分别验证分钟格式与 `yyyy-MM-dd HH:mm:ss`；已有 `2026-02-27 15:08:05` 打开后直接确认、取消或修改其他字段均不丢失秒；修改秒后只提交一次新快照。所需精度不支持时明确阻断而非归零。
- 逐一打开 Date、DateTime、Time、DateRange、Select、User、Department、Lookup 和 File 的实际控件；面板不横向溢出、不被裁切、不被底部操作栏遮挡。
- 人员／部门多选触发器显示完整的可换行标签；选择 Sheet 的头像／部门简称、顶部横向滚动和右侧勾选在窄宽度下完整可见。附件按标准卡片展示缩略图／图标、状态、删除确认和虚线上传入口。
- 软键盘打开后当前字段、错误信息和必要操作仍可到达；关闭后滚动位置合理。
- 在真实 iOS Safari 与飞书 WebView 中逐一聚焦文本、数值、长文本及弹层搜索框：页面不应自动放大或横向偏移，左侧标签保持完整，关闭键盘后保存按钮可点击，并能手动双指缩放；同时回归 Android 与桌面。
- 使用键盘 Tab 检查输入、选择触发器与 Sheet 操作的 `:focus-visible` 指示可见；手机常态仍无盒状边框，焦点变化不改变字段行高。
- 保存／提交使用 `MobileFormActionBar`，按钮无图标并靠右；安全区、loading、disabled 和防重复提交正确。详情编辑／删除操作才使用 `MobileBottomActionBar`。
- 返回 desktop/tablet 后，原 Drawer、桌面控件和表单值保持正常。

仅验证“全屏页头出现”、静态 DOM、单元测试、类型检查或构建通过，不能证明手机表单已完成。无法进入真实业务页面或无法打开实际字段弹层时，必须记录 blocker，不得宣称移动端新建／编辑／详情适配完成。
