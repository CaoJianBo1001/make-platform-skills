# Make App 移动端产品基线

## 规范地位

本文件是 Make App 手机端展示与交互的规范性冻结移动端基线。生成新 App、改造存量 App 或审查移动端实现时，先以本基线判定产品形态，再按其他 reference 落实组件、权限、数据和测试细节。

存量 App 的适用范围见本文末尾的“优先级”；单纯 PC 修复不触发移动迁移。

历史方案、早期设计稿和已经被产品复盘推翻的实现不得覆盖最终基线。只有用户对当前项目提出明确的特殊要求时，才允许偏离对应条目；偏离必须记录范围，不得反向改写平台默认。

本基线描述通用产品合同，不依赖某个试点仓库、业务对象、字段名、颜色值或本地源码路径。参考实现的来源快照只记录在仓库变更记录中，Skill 使用者不得复制业务代码来代替公共组件和宿主适配层。

## 页面矩阵

| 场景 | 手机端最终形态 | 不允许的替代 |
| --- | --- | --- |
| 应用壳层 | 头像入口、账户抽屉、最多五项底部导航、独立工作台 | 桌面侧栏缩窄后继续显示 |
| 对象列表 | 独立紧凑 toolbar，默认使用中号搜索框；筛选能力已启用或本次明确请求时，才同排显示中号筛选按钮。扁平记录卡片、列表内滚动并在顶部下拉刷新、悬浮新建 | CanvasTable、桌面工具栏纵向堆叠、分组、排序、记录批量操作；不显示独立刷新按钮或刷新图标，未启用筛选时不显示空筛选入口 |
| 新建／编辑 | 可寻址全屏任务路由、移动字段适配器、底部保存区 | 桌面 Drawer 放大或只改成一列 |
| 详情 | 可寻址全屏任务路由、只读标签／值行、值靠右、Tab 与正文共用左右留白、按独立权限显示底部编辑／删除 | disabled 表单、值靠左、Tab 全宽贴边、因卡片已有操作而取消详情操作 |
| 日期／时间 | 底部 Sheet 中的滚轮或单月日历，确认后提交 | 桌面日期面板、原生输入作为平台默认、上下两个范围输入框 |
| 候选选择 | 普通选项、身份、Lookup 按各自提交与搜索合同展示 | 所有字段无差别套用搜索选择器 |

## 共享与分离边界

- desktop/tablet 与 phone 共享 Schema、权限结果、记录请求缓存、表单 Controller、值归一化、校验和写入合同。
- 两端分别挂载自己的 View、toolbar、列表／表格、字段适配器和覆盖层；不得同时挂载两棵业务树后用 CSS 隐藏。
- 宽度切换只改变展示组件，不重建业务 Controller，不重复请求，不丢失表单草稿、查询上下文或列表恢复状态。
- 操作选择遵循 `make-app-actions` 的实例生命周期：CanvasTable 卸载时清空选择并使旧操作失效，返回桌面不回放旧选择；不以保留业务草稿为由保留旧写目标。
- 公共移动包提供壳层和通用交互原语；宿主负责业务路由、数据、权限、候选请求、字段注册表和提交生命周期。
- 公共移动包同时提供人员／部门字段和附件字段的标准视觉组件；宿主只注入受控业务值、候选、附件状态及请求回调，不在项目内重新拼装标签、身份标识、附件卡片或删除确认。

## 优先级

本节是所有移动 reference 的唯一优先级定义。新 App 默认适用；存量 App 仅在用户明确要求移动适配或响应式改造时迁移本次范围，普通 PC 维护不自动改造移动端或扩大业务范围。进入移动改造范围后，既有桌面实现不能作为跳过手机合同的理由；用户明确要求保留的特殊行为按第 1 项记录为项目例外。

1. 当前用户对本项目的明确特殊要求。
2. 本冻结基线及其直接链接的专题合同。
3. desktop/tablet 通用规则和项目既有视觉约定。
4. 历史设计、旧变更记录或试验性实现。

低优先级规则与高优先级规则冲突时，必须采用高优先级规则并修正测试；不得通过“沿用现有桌面组件”规避手机端合同。
