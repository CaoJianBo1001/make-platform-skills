# 页面设计基线与视觉验收

所有新 Make App，包括 POC 和模板项目，在选定组件库及视觉来源之后执行：先记录设计基线，再生成真实业务的代表页面，验证后复用到其余页面。已有项目复用已确认的基线，本次变化涉及哪个区域就更新哪个区域；小修改不触发全站重设计。此文管理生成质量，不新增组件库、公共包或 MakeDesign 协议。

## 生成前的设计基线

在项目既有设计文档中记录；没有时使用 `docs/ui-design.md`。用简短表格说明决策与来源，不要求用户填写长问卷。使用场景、主要任务与品牌方向先取已确认 PRD／描述；影响版式的关键信息未明确时集中询问，不从演示页面推断业务。已确认的选择直接复用，不再次询问。

| 内容 | 必须说明的决定 |
| --- | --- |
| 使用场景 | 使用者的任务、阅读／录入顺序、数据密度；不增加 PRD 之外的字段、指标或功能 |
| 组件库 | 项目唯一主 UI 库、实际版本、官方主题入口及所需控件覆盖；Make 公共包另列版本与职责，组件库完整不代表安装其全部组件 |
| 视觉来源 | 原方案 URL／用户参考／组件库默认主题；已解析风格、导航、表面及有效布局选择，数值与来源一起保存 |
| 区域 | Shell、标题、工具栏、主体、表单分区／详情信息、操作区的排列与滚动归属；页面／抽屉容器及选择来源 |
| 视觉尺度 | 按角色的字体与字号、页面边距、分区和字段间距、控件高度、圆角、边框、表面与语义色；区分方案明确值、官方或 Make fallback，避免多层 padding 叠加 |
| 移动适配 | 冻结手机合同、实际安装包、独立 View、字段行、任务页／底栏、候选弹层与桌面共享的状态；只同步主题主色／选中强调色，不继承 PC 其他视觉与布局；手机未覆盖项单列 |
| 代表页面 | 本项目列表、新建、编辑、详情及对应手机 View；无该功能时标不适用并说明 PRD 依据 |
| 差异与验收记录 | 所选值的适用／不适用／未支持、公共包主题后续同步、截图与交互检查、设备覆盖及待验项 |

组件库与视觉来源分别按 [组件选择](component-usage.md#selection-strategy) 决策：用户指定库优先，Skill 选择沿用结果，MakeDesign 未另指定时默认 Ant Design。每个新项目都有完整、可用的项目控件体系；不能只引入颜色文件，再临时手写日期、选择、校验与弹层。沿所选库和已有 Make 公共组件的公开能力做业务适配，不因主题附带另一库的资产而混装。

PC宿主搜索、列表单条命令、表单操作和弹层都使用所选主库或已有Make封装组件，按同一主题／规格保持高度、字形、边框、圆角、留白和禁用／loading语义。记录操作继续由make-app-actions决定资格与执行链；不要为方便验收在普通页面额外保留浏览器默认外观的编辑／保存按钮。确需隔离测试入口时只在明确的QA入口出现；业务动作仍通过原组件及Controller验证。

## 规则优先级与稳定合同

PC／平板已选方案明确的视觉值和已支持布局选择优先于对应默认；无值时记录所选库官方或 Make 合同 fallback。手机只跟主题主色及对应选中／强调色，字体、字号、间距、密度、导航、控件与弹层样式沿原手机规范，不接受 PC 风格覆盖。方案没有表达的能力不假装已实现，也不从另一项目截图复制配色、尺寸或布局。完整应用与差异处理仍按 [方案应用](component-usage.md#完整方案应用与差异记录)。

Make 字段语义、权限、受控值、验证、候选来源、提交和审批资格是稳定合同，不被外观选择改变。桌面表单的纵向标签、紧凑详情、字段图标及普通／宽字段骨架继续按 [Drawer 标准](drawer-layout.md) 组合。所属容器的实际可用宽度、长标签和控件复杂度决定是否仍能排双列；窄容器可以改为单列，无需另问用户。不能因整块屏幕宽就挤压窄 Drawer 内的日期、多选或标签。

当前保留 60% 新建／编辑 Drawer 默认；普通详情已支持的 page／drawer／wide-drawer 服从有效方案。没有对应选择时沿用现有 Make 默认，不提前新增 page／modal／drawer 选择协议或产品配置器。审批、分析汇总和手机任务容器沿各自 Skill，不从普通详情推导。

桌面列数、标签方向、宽字段跨列、控件高度等默认不得覆盖冻结手机合同。视觉默认也不能削弱滚动归属、键盘焦点、关闭回焦、弹层不裁剪和独立状态反馈。

## 页面组织与视觉节奏

- 列表保持清楚的标题／工具栏／数据区层级、左右对齐及主次操作；不为显得丰富添加重复标题卡、无用概览、分页或功能入口。主内容填满其工作区，信息少时保持合理阅读宽度，不把少量字段摊满超宽区域。
- 表单按已确认业务关系及录入顺序分组；默认双列下相关短字段相邻，长文本、复杂关联及附件按桌面字段合同跨列。少量字段不制造空分区，复杂表单先梳理分组，不无条件增加卡片、Tabs 或步骤。分组只组织已授权字段，不改变字段资格或写入规则。
- 详情保持紧凑的标签／值阅读顺序；用正常信息层级呈现重要内容，长值换行、日期与范围按类型格式化、空值统一。不能用禁用表单替代只读详情，也不为未返回值生成大空框。
- PC 页面标题、记录容器标题、分区、字段、控件和辅助文字按 [字号角色](business-typography.md) 分别消费当前风格；手机保持原移动字号角色和触控尺寸。保留用户明确的适用端微调，不通过全局大字号或统一缩字表达风格。
- 页面边距、分区间距、字段间距分别有来源，标签、控件、错误提示和操作区共享对齐线；真实控件填满所属值槽。包装控件也需透传公开 style／className，按 [组件接入](antd-foundation.md#主题字段与布局) 核对所选库的实际能力，非 AntD 项目使用自身公开入口。
- 品牌色、表面、文字、边框及状态使用各自语义，不把同一主色铺满所有区域；保留方案明确主题及状态值，主次操作有层级。公共包自有区域暂按正式能力展示，记录差异。

## 手机保护与相关 Skill

手机继续由 [冻结产品基线](mobile-product-baseline.md)、[移动默认](mobile-defaults.md)、[字段规范](mobile-form-controls.md)、[视觉标准](mobile-visual-standard.md)、[公共详情组件](mobile-detail-components.md) 和 [表单验收](mobile-form-acceptance.md) 定义。此文不重新定义手机排版或控件，不把桌面表单缩成手机版。共享业务 Controller、草稿与缓存，只挂当前 View；切换宽度不得新增一套业务状态或请求链。

按正式移动 0.1.16 或已等价验证的兼容正式版本检查宿主实际解析产物，不能只读 package.json 声明。手机字段保持既定同行左标签／右值，只有 File 可采用上下全宽；字号角色和可编辑输入的 iOS 安全下限分别检查。全屏任务路由、正文滚动、表单底栏与详情操作栏沿对应公开组件；不能用桌面纵向标签、全行 TextArea、抽屉或日期弹层覆盖它们。

新质量基线不默认增加公共包完整主题改造，也不覆盖包私有 CSS。手机宿主和已支持的正式移动组件只通过 [颜色投影](../assets/mobile-brand-theme.mjs) 与其 [类型](../assets/mobile-brand-theme.d.mts) 同步主题主色及选中／强调色，组合方式见 [手机颜色接入](mobile-theme.md)；不传整份 PC mapper，不继承 PC Provider 的字体、尺寸、背景／控件表面或导航。Canvas、审批等其他引用包的完整主题仍列后续同步。触控、safe-area、单行多动作／更多、候选确认及取消、远程候选反馈继续按原手机合同验收。涉及记录动作时读取 [手机记录操作](../../make-app-actions/references/mobile-card-actions.md)，审批任务／独立填单读取 [审批移动合同](../../make-app-approval/references/mobile.md)，筛选、AI 等仅在本项目功能已触发时交给对应 Skill；视觉改进不修改其业务资格。

## 代表页面到全项目

列表与手机 Lookup 的可复制组合及六项交付检查统一维护在 [宿主组合示例与交付门禁](record-page-patterns.md)。生成前读取它并选择适用模块，生成后执行对应的行为／DOM 检查与真实浏览器检查；文档中写了“遵循 Make 标准”不能代替这些证据。列表搜索、授权新建入口、Lookup 确认和手机冻结视觉均为代表页面的一部分，不能在 POC 或模板中省略后仍宣称代表页面通过。

先用本项目真实字段与实际组件完成列表、新建、编辑、详情和手机对应 View，包含本项目存在的长标签、日期／区间、单多选、人员／Lookup、长文本、必填及只读字段。验证完成后复用该组合生成其他对象，并覆盖其字段差异；不能只用两三个短文本字段证明整体质量。业务尚未接通时可以在隔离验收项目 mock 服务边界并注明，不能把演示数据带入业务 App。

Agent 在既有授权内自行检查和修复，不要求用户逐页批准。不要给产品添加设计验收面板、选库器或换肤器；测试入口仅在隔离验证环境使用。没有选择过的业务模块不因设计样例出现而生成。

## 视觉与交互验收

自动测试通过不等于视觉验收通过。对真实页面截图、计算样式和元素边界共同复核；记录比较结论及修复，不以截图文件存在、data 属性、主题变量或主色相似代替验收。

| 覆盖 | 核对内容 |
| --- | --- |
| 桌面／平板 | 宽桌面、普通笔记本及窄内容容器；列数按实际内容宽度适配，检查控件填槽、标签／错误无重叠、长值、空字段、分区与操作区；保留现有边界模式 |
| 手机 | 320／390／767px 及 768px 边界；列表、任务页、详情、底栏、候选 Sheet 与日期；检查无横向溢出、底部入口无遮挡、正文滚动、字段同行、长多值与附件、safe-area；触控点击不增加盒状焦点框，Tab 焦点可见且行高不变，和桌面切换时状态保持 |
| 风格与库 | PC 按本项目方案逐项比较 Shell、颜色、字体角色、间距、密度、控件与弹层；手机对比默认和方案下同一专用控件及非颜色样式保持，只改变主色／选中强调色。Skill 维护时用新 POC 和模板、两个明显不同方案及组件库默认主题验证，指定非 AntD 时检查不混入另一库 |
| 命令与标签 | 逐一核对PC宿主按钮与同主题主库参照的计算样式／实际高度，表格外也不能遗漏；点字段标签可聚焦相应原生控件，实际可访问名称与字段名一致。完整字段adapter的默认测试覆盖标签／id接线，不能只验证可见标签文字 |
| 内容与状态 | 实际长标题／标签／多值，空数据、零字段、加载、错误／重试、必填、禁用；没有无意义空卡、重复边距、截断或乱序 |
| 实际操作 | 输入、选取、清空、取消、校验、保存及重开；显示值与最终 payload 一致，日期边界／精度、多选和候选切换正确；弹层可见且可点，键盘／Escape／关闭回焦按既有合同 |

将结果分为通过、失败、不适用和待验；后两项说明依据或缺口。真实组件测试、浏览器尺寸仿真、真机／飞书分别报告；软键盘与真机未测须标为待验，不用桌面手机仿真冒充。已选风格被默认值覆盖、关键字段或操作不可达、手机冻结合同退化及可复现视觉缺陷需先修复；其他明确不在本轮的公共包主题或设备缺口如实保留，不声称全部设备／所有项目质量已获证明。
