# 前台审批完整接入验证

先将本次触及的场景落到宿主已有测试：纯字段/状态函数单测，保存编排调用顺序和次数测试，UI 按钮与可见性测试，Service 权威校验及请求合同测试。保留普通 IAM 回归，不复制审批函数到测试里计算期望。

节点字段转换先执行 `node skills/make-app-approval/scripts/verify-node-form-metadata.mjs`，覆盖随包 [转换合同](node-form-metadata.md) 的真实参考函数；宿主可传入桥接自身转换代码的 ESM 文件复用同一测试。仓库 `scripts/test-bpm-node-form-metadata-behavior.mjs` 另验证故障注入会被发现，CI 的 `scripts/test-*.mjs` 入口会自动运行。`test-bpm-node-form-metadata-contract.mjs` 仅检查文档来源与链接，不作为转换行为或真实 Workflow 联调证据。

## 默认生成决策场景

| 已确认需求 | 应观察的结果 |
| --- | --- |
| “客户可登记资料并保存”，没有审批字样、尚未绑定流程 | 生成一个入口；对象普通保存，无首次发起按钮 |
| “每天录入销售目标”，多个对象都有录入页 | 一个应用级入口，PC/手机复用 |
| “经理只处理审批待办，不建申请页” | 生成入口，不擅自新增业务新建页 |
| “订单只读查询，提交搜索条件” | 不触发入口；不能关键词误判 |
| 只有看板、登录、筛选或数据表定义 | 不触发入口 |
| 纯查询应用迭代加入可保存的业务编辑 | 补齐入口，重复执行不重复导航 |
| 已接入应用无当前任务、流程全部停用/解绑 | 入口和历史路由保留；无任务与未接入明确区分 |
| 新项目有录入功能，生成时无 key，之后启用流程 | 首次生成已具备动态适配；刷新/重开后出现审批字段和双按钮，不重新生成代码 |

## 导航布局场景

| 场景 | 可观察断言 |
| --- | --- |
| 桌面/平板存在多个对象与模块分组 | “我的审批”只出现一次，作为一级菜单紧接所有业务对象/模块分组之后；同一导航列表、相同行间距，无单独分隔线、卡片或底部区域，不属于任何分组、对象或子菜单 |
| 对象较少、窗口高度增加 | 审批项仍紧跟最后一个业务入口，二者间距不随侧栏高度增大；不被弹性占位、自动外边距或固定定位推到底边 |
| 折叠全部对象分组、调整对象顺序、对象列表变化 | 审批项不随分组折叠而隐藏，始终是一级兄弟项，随前方菜单高度自然移动并排在业务入口之后；既有侧栏收窄模式仍保留可识别、可点击的审批入口 |
| 业务导航超长、侧栏滚动 | 业务菜单与审批项在同一滚动区域自然滚动，滚到菜单末尾可访问审批；允许它随滚动移出可视区，不固定悬浮，也不引入整页滚动 |
| 已有审批入口错误挂在某个对象下，或被固定在侧栏底部并分隔 | 移至业务入口之后的一级菜单位置，去掉审批专用固定区域、分隔和占位；原路由和导航标识不变，旧位置没有重复入口 |
| 切换到手机 | “我的审批”占一个独立底部 Tab，复用同一应用级路由和标识，不嵌入对象或工作台网格，总数不超过五项 |
| 有审批、有 AI，业务对象从 3 个增至 4 个 | 从全部对象、审批、AI 切换为前两个对象、审批、AI、工作台；审批不计入业务对象数 |
| 有审批、无 AI，业务对象从 4 个增至 5 个 | 从全部对象、审批切换为前三个对象、审批、工作台 |
| 权限刷新、对象减少、AI 可用性变化或业务对象为零 | 从同一权限快照重算业务入口；审批保留，工作台直达路由和当前页面保留，不用加载中的空列表提前判断 |
| 手机进入新建／编辑／详情后返回根页面 | 任务页不叠加根底部 Tab，返回后只有一组导航，审批没有重复入口 |
| 未生成审批入口的应用 | 保留原有 5 个业务对象的工作台 Tab 阈值及导航顺序 |

## 桌面审批头部位置验收

以宿主真实渲染和浏览器布局验证，不只断言页面中出现某段文字。所有状态 Tag 均遵守相同位置，不能只修正“审批中”。

| 场景 | 可观察断言 |
| --- | --- |
| 业务详情存在流程状态 | 左侧 DOM 与视觉顺序为全屏、详情标记、原标题、状态 Tag；Tag 的前一项为标题，右侧 actions 中没有状态 Tag |
| 业务详情符合首次发起或撤回条件 | 发起审批/撤回位于右侧操作组，最后一个按钮为唯一的关闭 X；独立发起不依赖普通编辑资格，编辑/删除仍遵守原入口归属 |
| 新建审批表单双动作 | 保存、保存并提交、关闭 X 按顺序位于右侧；左侧只含全屏、模式与标题；无重复底栏 |
| 包任务详情加载完成 | 左侧为全屏及按 [状态合同](status-display.md#展示合同) 接入的标题组，其中“审批详情”后紧跟一个真实状态 Tag；覆盖包旧名称需宿主适配的情况，右侧仍为包授权 actions，关闭 X 始终最后；动作不因位置调整而增删或重排 |
| 长标题、窄桌面/平板、切换全屏 | 状态 Tag 仍紧邻标题，不被推到右侧、不覆盖操作；标题按溢出省略且可查看全文，按钮可操作；详情按钮不继承表单放大规则 |
| 状态缺失、加载中或加载失败 | 不出现空 Tag 或多余间隔，标题组与关闭位置稳定；不显示推测的审批状态 |
| 标题公开插槽替换 | 用真实包覆盖加载、失败重试、成功和全屏，核对标题语义及计算后的字号、字重保持一致；成功只显示一个状态标签，不能仅检查文案或类名 |

## 宿主行为矩阵

| 场景 | 可观察断言 |
| --- | --- |
| Schema 成功且无 key | 普通字段集，保存不调用启动配置/发起接口 |
| 启动配置 field 为 key 或完整对象 | 可见 key 按启动顺序从一次 START 节点元数据补齐；隐藏 key 缺定义不阻断，完整对象不额外读取；不从 Schema fields/createFields 兜底，不加入节点定义中未授权字段 |
| 有 key、启动配置加载或失败 | 正确加载/错误与重试；没有普通字段回退或未授权提交 |
| 普通 createFields 不含 F，启动配置允许 F | F 正常显示且能保存；UI、Service 均不再做 IAM 字段交集 |
| 可读不可写、隐藏、可读可写字段 | 分别只读、消失、可输入；注入隐藏/只读值被拒绝或从白名单移除 |
| 标准类型和 Make.Field.ID | 复用类型控件；ID/流程状态/锁不进入写入载荷 |
| 实际启动配置字段同时有 `type: "Make.Field.Number"` 与 `makeFieldType: "NUMBER"` | 用两份真实返回的精简夹具验证包装层按 Service 合同解析，以已识别的 `Make.Field.*` 作为宿主标准类型并按已确认映射核对枚举；Number 精度、多选选项、Lookup 关联、文件上限、金额及百分比属性不丢失；冲突时报合同错误 |
| 其他版本出现数字 `type` | 仅按该版本已确认的接口合同和真实样例归一化；含义未明时报错，不假定本端点的字符串规则适用 |
| 缺少类型、未知类型、重复 key、非法权限 | 明确配置错误，不降级文本、不漏字段后继续提交 |
| 两个保存动作的必填及类型校验 | 校验失败时创建和发起均为零次；保存不绕过必填 |
| 手机审批表单与仅支持单动作的移动组件 | 保留两个独立按钮；复用宿主双按钮组合，不传虚构 API，不挂两个固定底栏 |
| 仅保存 | 创建一次、发起零次；保存成功不是审批状态 |
| BPM 新建仅保存后重新查看并编辑，PC/手机 | 明确未提交、未锁定且有效绑定时编辑页有保存/保存并提交；详情保留独立发起且不要求普通编辑权限。编辑页前者只更新，后者更新原 ID 后发起；不重新创建、不读取启动字段，状态变化或更新失败时不发起 |
| 新建保存并提交 | 仅一次 bpm-process-submit；普通创建及旧 bpm-process 发起均为零次，最终 data 保留合法关联和附件 |
| 发起人单部门/多部门/空数组 | 单部门自动使用；多部门未选不能确认、确认传所选 ID；明确空数组省略参数交后端校验。仅保存及任务 SUBMIT 不查询部门 |
| 部门选择取消、查询失败、身份/对象切换 | 不创建、不更新、不发起；不将失败或缺失 departments 当作空数组，迟到响应不继续写入 |
| 新建合并提交业务失败，落库结果未确认 | 使用真实请求解析链路，覆盖 HTTP 200/code 非 200 及 HTTP 4xx；保留原错误、Trace、表单和上传结果，无虚构的已保存恢复态、无核查流程按钮。再次点击保存并提交或改点保存，创建、提交、旧发起请求次数均不增加；不以错误码或 HTTP 状态推断可重建 |
| 写请求发出前的字段校验、部门查询、附件预上传失败 | 创建、提交、发起均为零，未进入写结果待确认状态；修正后可再次提交，复用已确认的上传结果 |
| Schema、权限或启动配置预检查失败 | 预检查失败时发起请求数为 0；创建前失败时创建数也为 0，错误态可重试且不自动发起 |
| 已保存后发起前检查失败 | 重试保持原 `recordID` 和上传结果；创建/上传次数不增加，重新检查通过后才发送一次发起请求 |
| 保存明确失败/结果未知 | 不发起；结果未知不允许盲目重复创建 |
| 已有记录更新成功发起失败后重试 | 原 ID 不变，创建/上传次数不增加；失败反馈区分两个阶段 |
| 发起响应的 HTTP 状态与业务码组合 | 使用该接口已确认的成功/明确拒绝/结果未知合同；保留码和状态，不能只看 HTTP 或复用另一项目的错误码映射 |
| 重复点击、发起超时 | 拦截会话内重复操作；未知结果先核查，不自动重发 |
| 附件和 Lookup | 附件未完成不创建；关联按现有格式和目标授权；失败保留上传结果 |
| 审批独有 Lookup 或 File 字段 | 即使不在普通 `createFields`，也以最新启动配置核对源字段和类型能力；Lookup 使用启动字段的关联元数据并继续校验目标可见性，File 只在已确认的预上传合同下提交后端认可的附件值 |
| 配置停用、字段授权变化、对象/身份切换 | 重新核实、拒绝旧结果，保留已保存 ID，不自动提交历史记录 |
| 开始直达结束 | 状态采用后端终态，不伪造审批中或人工待办 |
| 首次发起成功后的即时回显 | 分别让响应的 `processStatus` 返回 `IN_APPROVAL`、直接返回 `APPROVED`；紧接着同一记录的列表查询返回状态缺失、空值或 `UNSUBMITTED` 时，列表、详情和标题仍显示响应的真实状态；后续查询返回非空真实状态时采用查询值，其他记录不受影响；仅保存、发起失败或结果未知不套用此回显规则 |
| 长字符串 recordID | 保存、发起、回显值完全一致，无 Number 精度损失 |
| 普通已有记录编辑 | 保持原 IAM/更新链路；不读取新建启动字段授权扩大编辑范围 |
| 审批中、RETURNING、APPROVED、REJECTED、CANCELLED、明确锁定 | 按下述普通编辑禁编矩阵验证，三种终态即使未锁定也只读，缺失状态的关联锁也生效 |
| 流程状态列、详情字段、标题 Tag | 共用状态映射；字段按 key 去重、只读，缺失值不显示标题 Tag |
| 对象解绑后返回历史状态 | 显示真实记录状态；不因当前 key 消失把历史改成未发起 |
| 系统字段在记录映射、分页/分组叶子、手机卡片 | 状态和锁无损保留，不逐行额外请求状态 |
| APPROVED | 列表、详情字段、业务标题和任务详情头部均为“已通过”；timeline 的“已同意”不被改写 |
| RETURNING | 流程状态为“退回中”，timeline 的“已退回”不被改写；普通禁编、撤回和任务继续提交资格不变 |
| 未知非空状态 | 显示状态未知，不当作未发起、已通过或已撤回 |

### 普通编辑禁编矩阵

使用宿主真实操作栏、编辑路由和单元格桥接测试；不能仅测试状态函数或断言按钮 disabled。

| 场景 | 可观察断言 |
| --- | --- |
| `IN_APPROVAL` / `RETURNING` / `APPROVED` / `REJECTED` / `CANCELLED`，锁分别为 true、false、缺失；状态缺失但锁为 true | 即使 IAM 允许 update，普通编辑按钮/菜单也不在 DOM；业务列表、原有详情编辑面、卡片与单条选择入口一致；不影响正常详情读取 |
| 审批入口未启用、对象解绑或不展示状态列，但记录仍处于上述禁编条件 | 仍不渲染编辑入口；不能用展示开关或绑定状态解除禁编 |
| 同列混合可编辑与禁编行；鼠标、键盘、程序化单元格激活 | 仅符合普通权限且未禁编的行可打开编辑器；禁编行取消激活、不挂载输入框，最终保存/上传均为零 |
| 打开普通表单/单元格后记录进入审批或变为 APPROVED、REJECTED、CANCELLED；旧行快照触发保存、draft 接收或 `edit:end` | 使用最新记录拒绝旧会话；更新、附件上传、成功值回填均为零；直接编辑路由及绕过 UI 的普通更新同样被最终写接口拒绝，后端未上线时单独报告未验证项 |
| 多选范围内包含已知禁编记录 | 批量编辑入口不渲染，原选择保留，不静默过滤后写入；其他允许动作保持独立。未加载记录的预检拒绝仍阻止整个操作 |
| APPROVED / REJECTED / CANCELLED，锁为 true/false/缺失 | 三种终态均禁止普通编辑；撤回成功不能恢复编辑，任务办理和删除资格仍独立判断 |
| 0.2.11 原生仅覆盖 APPROVED；适配后覆盖三种终态 | 默认验证器应揭示原生缺口；`--compat` 验证参考组合通过，另验证 UI/Service 实际统一接线及最终拒写。保留包原有原因、锁优先级及异常，不将参考测试当成宿主验收 |
| 记录为 RETURNING，但当前 PENDING 任务授权编辑并提供 SUBMIT | 普通业务编辑仍隐藏；我的审批按当前节点字段/动作授权继续提交，不能套普通禁编条件阻断任务办理 |

## 撤回与恢复

| 场景 | 可观察断言 |
| --- | --- |
| UNSUBMITTED、缺失/null/空值、未知值及已锁定记录 | 只有明确未提交、未锁定且有有效绑定的记录显示发起；缺失与未提交的字段和 Tag 展示不同 |
| PC/手机可查看详情但无普通编辑权限，记录符合首次发起条件 | 详情仍有独立发起；即使普通编辑与删除均不可用，也不因此移除承载发起的操作栏；不显示普通编辑入口、不解锁字段。UI 仅调用原 ID 的 bpm-start，普通更新、关系保存及附件上传均为零；Service 不因缺少普通 update 权限拦截发起，Workflow 最终拒绝仍原样反馈 |
| 直接调用发起 Service、状态/绑定/锁变化、Workflow 拒绝 | 不借发起路由调用普通更新或扩大记录读取；失效状态不继续发起，拒绝不伪造成功。刚保存但无普通读权限按会话恢复合同检查，不强制 Data 回读 |
| 已有记录更新成功后发起失败，重复点击恢复 | 保留原 ID 与上传结果；重查确认后仅调用 start；已在途/终态只同步，不重新创建 |
| RETURNING、APPROVED、REJECTED、CANCELLED | 业务对象不再次 start；退回任务仅按 actions 的 SUBMIT 继续原实例，终态无重新发起 |
| 真实 starter、其他用户、缺失 starter、业务 applicant 与 starter 不同 | 仅可靠 starter 且实例未结束/审批中有撤回；不按业务字段猜测 |
| 撤回原因空白、1024 边界、重复点击 | 原因旁校验并聚焦；合法时一条请求，确认前重新核对流程，正文不带 bpmKey |
| 撤回期间流程已结束、响应不匹配、断网、成功后刷新失败 | 不盲目重发；失败保留原因；明确成功后不再撤回，刷新失败单独提示 |
| 撤回成功但锁仍为 true，或当前对象解绑 | 不本地解锁；按最新状态+锁+普通 IAM 判断编辑；历史仍可访问 |

### 历史表格高度与滚动

两个宿主历史落点均按 [高度与纵向滚动](history.md#高度与纵向滚动) 验收。记录实际 CanvasTable 版本、有效行高/表头高度、宿主高度上限及组件预留；预留保留，不以底部没有空白作为通过条件。

| 场景 | 可观察断言 |
| --- | --- |
| 空态、单条、少量且内容可容纳 | 空态可读；非空表格容纳表头、全部数据行和实际预留，不能因高度不足产生纵向位移；使用真实组件验证滚动范围，不能只断言容器 `style.height` |
| 高度上限前、恰好容纳、超过上限的临界记录数 | 容纳时无纵向滚动，超过上限才滚动；临界值依据实际生效的布局确定，不能以被测高度公式自身生成的期望值代替验证 |
| 多条记录；普通抽屉、全屏往返及窄容器 | 内容所需高度超过上限时表格内滚动有效；滚动到底后末行完整可见。窄容器出现横向滚动时，末行仍不被遮挡；组件底部预留仍保留 |
| 完整返回超过 20 条、滚动到末行 | 所有事件均可见，无前 20 条截断，不发后续分页请求，滚动范围不随视口变化丢失 |
| 刷新后完整列表变少或变空；全屏扩大可视区 | 高度重新适配，越界位置收敛，无旧行空洞；有效位置保持，尺寸变化不重复查询或重建实例 |
| 测量期间隐藏，再显示及连续切换尺寸 | 可测量后按最新数据与尺寸完成布局，无累计增高或尺寸反馈循环；卸载后监听器和延迟测量不再操作旧实例 |

使用已安装包的真实布局与滚动代码，不能把滚动范围模拟成高度公式的结果。逻辑测试若模拟绘图环境，须注明其范围；另在浏览器检查实际画布中的首行、末行、滚动条与预留，不能以辅助 DOM 表格或模拟测试代替视觉验收。项目测试可记录所测版本的实际读数，但不将其补偿值、行数上限或兼容算法推广为所有 Make App 的实现要求。

### Lookup 与普通字段的组合补丁

在当前节点同时授权编辑 Lookup 与文本/金额的场景中，分别覆盖“Lookup + 文本”和“Lookup + 金额”同次修改；仅通过当前授权且保存字段的 APPROVE／REJECT／SUBMIT 动作提交，包括退回提交节点后的 SUBMIT。RETURN 不适用本节的字段持久化断言，单独验证空 `recordPatch`、跳过业务字段校验与附件预上传。仅验证单独文本、金额或附件成功，不能代替组合补丁验收。

- 记录提交前各字段值与期望值；保留经过脱敏的本次 `recordPatch`、动作请求/响应及可获取的 Trace ID，关联同一环境、记录、实例与任务。
- 成功响应后使用具备相应读取资格的验收账号重新读取任务详情和业务记录，逐字段核对文本/金额值、Lookup 目标 ID 与关系展示，再核对状态、锁、后续任务与历史。不能只看成功提示、HTTP 200、出现下一待办或最终已同意。
- 将“动作流转成功”和“字段持久化一致”分别记录。任何字段仍为旧值、关系缺失或两处回读不一致，该组合场景均为**未通过**；不通过普通 PATCH 补偿，也不伪造本地成功值。
- UI 回读、接口请求与后续补验注明各自时间和来源；未采集的请求/Trace 明确记为缺失，不能用前次证据充当本次证据。修复后的通过结论必须来自同一组合场景的新验收记录。

## 退回／继续提交：按环境记录真实验收

参考适配器回归可在仓库运行 `node scripts/test-approval-host-adapters.mjs`；安装审批包的宿主可再运行 `node skills/make-app-approval/scripts/verify-task-detail-policy.mjs <host-ui-directory>`，直接检查包的公开 decoder、字段策略与动作构建器。它验证归一化与只读策略，不代表宿主界面或后端流转已验收。宿主需用实际安装的包补 UI/Service 测试。

是否具备 RETURN、允许退回哪个节点及后续可用动作，以本次环境的实际流程和任务响应为准，不沿用其他项目或旧流程的能力判断。每轮记录日期、backend context/profile、租户、App role 与运行时 appKey、应用构建/提交、审批包版本、processKey 及流程定义版本或可核验的发布标识。流程版本不可获取或历史记录缺失时明确注明，保留可获得的实例/任务定位与配置证据，不猜填版本，也不将旧记录自动视为新版本已验收。

在宿主验收文档中按具体路径、字段组合分别维护以下状态，链接对应证据；不要在可复用 skill 中写死某个项目的验收结论：

| 状态 | 记录要求 |
| --- | --- |
| 已真实验收通过 | 写明覆盖的环境、版本、路径与回读断言。已有退回提交节点、SUBMIT 或中间节点退回证据分别保留，不因另一组合失败而抹去，也不扩展为全部路径通过 |
| 已执行但未通过 | 保留实际请求、响应与不一致回读；例如 Lookup 组合补丁流转成功但字段未落库，仍是未通过项，不能被前端测试/构建通过覆盖 |
| 待真实验收 | 未执行的路径、缺少流程/账号条件、只有模拟验证或缺少关键证据的断言均单列待验；写明缺失条件，不因其他环境成功改为通过 |

以下是逐路径验收步骤，不能因单测通过填写为成功，也不要为完成测试擅自修改线上流程：

1. 在具备唯一 returnTarget 的测试流程中，分别准备可退回提交节点、可退回中间节点的 PENDING 任务；记录实例/任务/节点定位与精简响应。
2. 填写退回意见，观察一次 RETURN 请求、正确 targetNodeKey、空 recordPatch，业务字段校验/附件预上传/普通 PATCH 均为零；回读当前记录、待办和历史。
3. 用目标办理人的新待办重读字段授权与 actions。仅后端返回 SUBMIT 时展示“继续提交”；不把所有中间节点任务都推断为 SUBMIT。
4. 通过返回动作继续办理，记录实际 actionType；SUBMIT 时应沿用原记录与实例，产生后续任务/历史，不调用 start 或新建记录。核验字段保存、错误重试和成功刷新。

验收报告逐项记录前置条件、操作者资格、请求次数、响应与回读结果；未观察到的断言单列待验，不用模拟数据代替。退回提交节点后的 SUBMIT 与中间节点退回后的实际动作分别记录；每轮明确新增验收与复用的历史证据范围。

### Lookup 节点依赖回归
