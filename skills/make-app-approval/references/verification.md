# 审批生成与发起侧验证

先将本次触及的场景落到宿主已有测试：纯字段/状态函数单测，保存编排调用顺序和次数测试，UI 按钮与可见性测试，Service 权威校验及请求合同测试。保留普通 IAM 回归，不复制审批函数到测试里计算期望。

## 默认生成决策场景

| 已确认需求 | 应观察的结果 |
| --- | --- |
| “客户可登记资料并保存”，没有审批字样、尚未绑定流程 | 生成一个入口；对象普通保存，无首次发起按钮 |
| “每天录入销售目标”，多个对象都有录入页 | 一个应用级入口，PC/手机复用 |
| “经理只处理审批待办，不建申请页” | 生成入口，不擅自新增业务新建页 |
| “订单只读查询，提交搜索条件” | 不触发入口；不能关键词误判 |
| 只有看板、登录、筛选或数据表定义 | 不触发入口 |
| 纯查询应用迭代加入可保存的业务编辑 | 补齐入口，重复执行不重复导航 |
| 已接入应用无当前任务、流程全部停用/解绑 | 入口和历史路由保留；无任务与未接入明确区分 |
| 新项目有录入功能，生成时无 key，之后启用流程 | 首次生成已具备动态适配；刷新/重开后出现审批字段和双按钮，不重新生成代码 |

## 导航布局场景

| 场景 | 可观察断言 |
| --- | --- |
| 桌面/平板存在多个对象与模块分组 | “我的审批”只出现一次，位于最外层及导航底部独立区域，不属于任何分组、对象或子菜单 |
| 折叠全部对象分组、调整对象顺序、对象列表变化 | 入口仍可见可点击，层级和底部位置不变；既有侧栏收窄模式仍保留可识别、可点击的审批入口 |
| 业务导航超长、滚动至任意位置 | 仅上方业务导航滚动，审批入口保持在侧栏底部且不被遮挡；不引入整页滚动 |
| 已有审批入口错误挂在某个对象下 | 移至独立底部区域，原路由和导航标识不变，旧位置没有重复入口 |
| 切换到手机 | “我的审批”占一个独立底部 Tab，复用同一应用级路由和标识，不嵌入对象或工作台网格，总数不超过五项 |
| 有审批、有 AI，业务对象从 3 个增至 4 个 | 从全部对象、审批、AI 切换为前两个对象、审批、AI、工作台；审批不计入业务对象数 |
| 有审批、无 AI，业务对象从 4 个增至 5 个 | 从全部对象、审批切换为前三个对象、审批、工作台 |
| 权限刷新、对象减少、AI 可用性变化或业务对象为零 | 从同一权限快照重算业务入口；审批保留，工作台直达路由和当前页面保留，不用加载中的空列表提前判断 |
| 手机进入新建／编辑／详情后返回根页面 | 任务页不叠加根底部 Tab，返回后只有一组导航，审批没有重复入口 |
| 未生成审批入口的应用 | 保留原有 5 个业务对象的工作台 Tab 阈值及导航顺序 |

## 宿主行为矩阵

| 场景 | 可观察断言 |
| --- | --- |
| Schema 成功且无 key | 普通字段集，保存不调用启动配置/发起接口 |
| 有 key、启动配置加载或失败 | 正确加载/错误与重试；没有普通字段回退或未授权提交 |
| 普通 createFields 不含 F，启动配置允许 F | F 正常显示且能保存；UI、Service 均不再做 IAM 字段交集 |
| 可读不可写、隐藏、可读可写字段 | 分别只读、消失、可输入；注入隐藏/只读值被拒绝或从白名单移除 |
| 标准类型和 Make.Field.ID | 复用类型控件；ID/流程状态/锁不进入写入载荷 |
| 实际启动配置字段同时有 `type: "Make.Field.Number"` 与 `makeFieldType: "NUMBER"` | 用两份真实返回的精简夹具验证包装层按 Service 合同解析，以已识别的 `Make.Field.*` 作为宿主标准类型并按已确认映射核对枚举；Number 精度、多选选项、Lookup 关联、文件上限、金额及百分比属性不丢失；冲突时报合同错误 |
| 其他版本出现数字 `type` | 仅按该版本已确认的接口合同和真实样例归一化；含义未明时报错，不假定本端点的字符串规则适用 |
| 缺少类型、未知类型、重复 key、非法权限 | 明确配置错误，不降级文本、不漏字段后继续提交 |
| 两个保存动作的必填及类型校验 | 校验失败时创建和发起均为零次；保存不绕过必填 |
| 手机审批表单与仅支持单动作的移动组件 | 保留两个独立按钮；复用宿主双按钮组合，不传虚构 API，不挂两个固定底栏 |
| 仅保存 | 创建一次、发起零次；保存成功不是审批状态 |
| 保存后首次发起 | 创建一次，之后以返回的原 ID 发起一次，严格先后关系 |
| Schema、权限或启动配置预检查失败 | 预检查失败时发起请求数为 0；创建前失败时创建数也为 0，错误态可重试且不自动发起 |
| 已保存后发起前检查失败 | 重试保持原 `recordID` 和上传结果；创建/上传次数不增加，重新检查通过后才发送一次发起请求 |
| 保存明确失败/结果未知 | 不发起；结果未知不允许盲目重复创建 |
| 保存成功发起失败后重试 | 原 ID 不变，创建/上传次数不增加；失败反馈区分两个阶段 |
| 发起响应的 HTTP 状态与业务码组合 | 使用该接口已确认的成功/明确拒绝/结果未知合同；保留码和状态，不能只看 HTTP 或复用另一项目的错误码映射 |
| 重复点击、发起超时 | 拦截会话内重复操作；未知结果先核查，不自动重发 |
| 附件和 Lookup | 附件未完成不创建；关联按现有格式和目标授权；失败保留上传结果 |
| 审批独有 Lookup 或 File 字段 | 即使不在普通 `createFields`，也以最新启动配置核对源字段和类型能力；Lookup 使用启动字段的关联元数据并继续校验目标可见性，File 只在已确认的预上传合同下提交后端认可的附件值 |
| 配置停用、字段授权变化、对象/身份切换 | 重新核实、拒绝旧结果，保留已保存 ID，不自动提交历史记录 |
| 开始直达结束 | 状态采用后端终态，不伪造审批中或人工待办 |
| 首次发起成功后的即时回显 | 分别让响应的 `processStatus` 返回 `IN_APPROVAL`、直接返回 `APPROVED`；紧接着同一记录的列表查询返回状态缺失、空值或 `UNSUBMITTED` 时，列表、详情和标题仍显示响应的真实状态；后续查询返回非空真实状态时采用查询值，其他记录不受影响；仅保存、发起失败或结果未知不套用此回显规则 |
| 长字符串 recordID | 保存、发起、回显值完全一致，无 Number 精度损失 |
| 普通已有记录编辑 | 保持原 IAM/更新链路；不读取新建启动字段授权扩大编辑范围 |
| 审批中、RETURNING、明确锁定 | 既有普通编辑和快捷入口不绕过锁，缺失状态的关联锁也生效 |
| 流程状态列、详情字段、标题 Tag | 共用状态映射；字段按 key 去重、只读，缺失值不显示标题 Tag |
| 对象解绑后返回历史状态 | 显示真实记录状态；不因当前 key 消失把历史改成未发起 |
| 系统字段在记录映射、分页/分组叶子、手机卡片 | 状态和锁无损保留，不逐行额外请求状态 |
| APPROVED | 列表、详情字段与标题 Tag 均为“已同意” |
| 未知非空状态 | 显示状态未知，不当作未发起、已同意或已撤回 |

## 范围与交付检查

- 未生成撤回按钮/API、审批任务办理、审批历史、流程图或 npm 包安装升级指令。
- 未往 DSL 新增 `qfei_process_instance_status` / `qfei_is_locked` 业务字段，也未改写已有业务生命周期状态。
- 已有任务中心复用原路由；未接入时明确说明，不用假数据或假空态冒充完成。
- 普通场景的权限审计/一致性验证继续适用；审批新建增加独立 UI/Service 一致性用例，不能删除原 IAM 测试或要求普通权限函数返回审批字段。

Skill 仓库执行元数据、引用闭包及现有跨 skill 合同检查；这些只能证明打包和规则接线完整。宿主功能需要按其真实命令执行相关测试和构建；真实保存/发起联调使用明确授权的测试记录，结果应单独报告。未运行的场景不能标记通过。

错误分类与取消用例必须穿过实际请求解析、缓存与 Service 边界，覆盖完整响应、业务码失败、断流/超时、配置刷新和共享请求取消；不能只模拟最终错误对象。对每个阶段断言创建、上传、发起的实际调用次数及已保存 `recordID`，避免只验证页面文案而漏掉重复写入。
