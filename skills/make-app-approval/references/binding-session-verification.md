# 绑定刷新与保存结果的宿主行为验证

在包含审批新建、保存／保存并提交及合法撤回能力的 App 中，按 [绑定会话顺序](entity-bindings.md#刷新取消与写入结果的顺序) 验证真实控制器。仅有任务处理能力、缺少适用能力或无法提供桥接时，记录适用范围及缺口，继续执行对应宿主测试，不能用合成夹具冒充该 App 通过。

## 运行方式

定位当前安装的 `make-app-approval`，将 `<skill-dir>` 和 `<host-adapter-module>` 分别替换为 Skill 目录及宿主 ESM 桥接文件的绝对路径，保留引号。Node 22+，可从宿主工作目录运行：

```bash
node "<skill-dir>/scripts/verify-bpm-binding-session.mjs" "<host-adapter-module>"
```

适配器必须导出 `createBpmBindingSessionHarness(options)`。验证器没有默认宿主或默认通过的参考实现，缺少适配器退出 2，场景失败退出 1；成功输出 6 项通过。也可在宿主已有测试框架中导入 `verifyBpmBindingSession(factory, {timeoutMs})`，默认每场景 5000ms；沿用宿主测试运行器处理 TS／React，不为此增加生产依赖。

场景超时或结束后，工具关闭该场景的测试 I/O；初始化超时后才返回的控制器只执行一次 `dispose()`，不再执行场景。工厂初始化若自行失败，应清理已创建但尚未返回的资源，工具只能卸载实际收到的控制器。

## 薄桥接合同

工厂每次创建隔离的真实宿主控制器或挂载真实表单，准备合法必填值和授权上下文。`options.bindingKey` 是本场景保持不变的绑定值；`withAttachments: true` 时准备两个会产生独立预上传请求的文件；`initialRecordId` 为 null 或合法撤回场景的已保存记录 ID。绑定、启动配置、身份、人员与节点等其他读取使用宿主现有测试夹具，不访问部署环境。

只将外部请求替换为 `options.io`，保留生产 UI → 请求适配器 → 控制器的编排及原错误分类；不要在桥接中补取消、缓存 ID、阻止重复创建、清理未知结果或重建权限判断。

| 外部 I/O | 桥接方式 |
| --- | --- |
| `io.upload({signal})` | 对接原预上传；测试结果 `{fileId}` 按宿主已确认附件 DTO 包装 |
| `io.write({kind, signal})` | 原创建为 create，新建合并提交为 submit，普通更新为 update；返回 `{recordId}`，按原 API 成功结构包装，不由桥接判断是否保存 |
| `io.start({signal})` | 对接原首次发起；本组场景中不应自动调用，不能偷偷在桥接中屏蔽 |
| `io.withdraw({signal})` | 对接原合法撤回，透传其实际取消信号；按宿主现有返回结构包装 |

验证器会暂停指定请求、使传输忽略取消后迟到成功，或在写请求已发出后抛出 TypeError 模拟断流。DTO／错误形状需要适配时，仅在原请求边界转换，不能把该异常声明为确定未写入。

工厂返回以下测试表面，命名只属于验证工具，不是新增 npm 或生产接口：

| 成员 | 要求 |
| --- | --- |
| `actions()` | 返回当前渲染／会话真实的 save、saveAndSubmit、withdraw 回调；验证器会保留旧引用后再次执行，不能使用调用时总是读取最新回调的代理掩盖旧闭包 |
| `refreshBinding()` | 触发宿主真实绑定刷新并完成同 key 重载；不能在桥接中自行推进代次或伪造失效状态 |
| `snapshot()` | 同步映射原状态 `{savedRecordId: string \| null, writeUnknown: boolean, bindingKey: string}`；绑定值须取宿主实际查询结果，不能根据请求次数、夹具 ID 或测试期望推算状态 |
| `flush()` | 刷新宿主已有测试框架中的渲染／微任务；指定外部请求仍暂停时不能等待它完成 |
| `dispose()` | 卸载真实组件／控制器，清理监听和测试资源；不重放写请求 |

## 场景和证据

验证器逐项观察真实外部调用次数、请求类别、取消信号和原会话状态：

1. 首个预上传暂停时刷新同一流程 key，释放后不继续第二个上传、写入或发起；因写请求尚未发出，不进入写入结果未知状态，也不伪造已保存 ID。
2. 普通创建已发出时刷新，可靠成功响应迟到仍保留原 ID；响应续行和旧回调重入分别检查，不能新增更新等写请求。新会话的合法普通更新不在此禁令内，但不能再次创建。
3. 新建合并提交的同类迟到结果保留 ID，旧操作及旧回调不能新增写请求；仍只有一次 submit，不能改成先 create 再 start。
4. 普通创建断流后刷新、旧回调重入及切换保存意图，未知结果保护保留，不新增写请求。
5. 新建合并提交断流的同类场景同样保留保护。
6. 合法撤回在绑定刷新期间保持自己的请求信号，不重复撤回或触发创建／发起。

这组固定场景保持同一身份和对象，不能证明跨身份隔离。宿主还需按 [完整验收矩阵](verification.md#宿主行为矩阵) 独立覆盖身份／对象切换、真实权限、HTTP 及业务失败分类和后端回读；旧结果只能归属原会话，不能进入新表单。一次工具通过不代表真实飞书或浏览器已验收。

升级 Skill 或替换验证器后，核对新增及变化的场景，使用当前工具重跑宿主桥接并记录 Skill 版本、宿主版本和实际命令。旧版测试通过不覆盖新增验证器；尚未接入真实控制器时明确记为未运行，不能用本机 Skill 已更新或仓库夹具通过替代宿主证据。

源仓库的合成控制器和故障注入只校验本验证器能拒绝错误实现，不随 Skill 分发，不作为 App 生成模板。各 App 应提交调用生产代码的薄桥接及自身测试证据；持续门禁采用项目内工具或版本化依赖，不把维护者本机路径写入 CI。
