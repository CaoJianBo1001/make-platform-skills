# BPM 独立新建与任务页

适用于需要从飞书三方审批或其他业务深链直接进入填单、待处理／已完成任务详情的 Make App。按已确认需求接入；已有对象抽屉及“我的审批”入口继续复用。此能力不实现飞书配置、通知中心、Bot、流程引擎或实例级详情。

新 App 按 [默认生成规则](generation-rules.md) 接入审批能力时同步准备适用的独立入口，运行时依据真实 BPM 配置及权限决定能否使用。只有任务处理能力的 App 不增加业务新建功能；存量 App 按当前确认范围迁移。

## 统一管理与各 App 的职责

Console 是所有 Make App 共用的管理端。每个 App 的开发者、业务对象、字段、控件和页面结构可以不同；独立审批页使用各 App 的真实业务能力。

| 责任方 | 负责的能力 |
| --- | --- |
| 统一 Console | 配置流程、启动／节点字段权限、飞书接入及发起范围；查看管理状态和同步异常 |
| 平台后端／BPM | 提供已配置的元数据、权限和任务动作；校验当前 App／环境及操作者；执行提交、流转、飞书同步和最终授权 |
| 各 Make App | 提供标准业务深链；复用自身表单和办理逻辑，消费后台配置并展示可填写／可查看内容 |
| makecli 与 Skill | makecli 沿用既有应用／部署入口和预检能力；Skill 指导调研、生成、适配和验收，不在运行时替代后台配置或授权 |

App 不生成一份自己的 Console、流程设计器或飞书管理配置，不固化某次 Console 配置得到的字段、节点或发起范围。切换对象、节点或配置后，仍从对应的现有权威接口获取定义及授权。

## 地址合同

每个 App 使用自己的部署 origin，动态片段使用稳定 key、字符串 ID 和 URL 编码。

先核对宿主已有 `/bpm` 路径、部署 basename、路由模式及代理／Service 的 SPA 回退，保证直接访问和刷新深链都能加载页面。冲突或不支持时明确具体兼容缺口，不静默改成另一个对外路径，也不改动 API 请求命名空间。

| 场景 | 路径 | 容器 |
| --- | --- | --- |
| 原有对象新建 | `/objects/:entityKey/new` | 保留宿主原有抽屉／手机任务页 |
| BPM 新建 | `/bpm/objects/:entityKey/new` | 无业务导航和列表的独立表单页 |
| 当前或历史任务 | `/bpm/tasks/:processInstanceId/:taskId` | 无审批列表的独立任务详情页 |

表中原对象 `/new` 是已有入口的示例。存量 App 没有该地址时保留其原有入口，不为 BPM 迁移额外改造普通导航和路由；标准 BPM 路径仍按表提供。

待处理和已完成共享任务地址，任务状态以每次后台响应为准。不能从 URL 的 status、readonly、来源标记等参数授予字段或动作权限；不能拿 recordId 代替 taskId。实例级详情只有在另行确认产品范围与访问接口后接入，不因本合同自动生成 `/bpm/instances/:processInstanceId`。

URL 不携带凭据。复用 [认证 Skill](../../make-app-auth/SKILL.md) 的登录与原地址回跳，保留完整 path/query/hash；已有有效会话直接进入原独立页，未登录则认证完成后回到原地址。字段使用实际登录的 Make 用户对应的 START／TASK 授权，不能由链接指定用户或权限。租户、应用、环境和身份由已有运行时及 Service 校验。飞书按钮入口资格由平台后端负责，App 不另建飞书发起范围判断或专用授权接口，也不为单独页面新建登录、OAuth 或跨域会话方案。

## 抽取边界

| 层 | 所有 Make App 共用的责任 | 各 App 适配的内容 |
| --- | --- | --- |
| 宿主表单会话／控制器 | 原新建入口（抽屉／弹窗／页面）与独立页调用同一套启动配置、字段授权、校验、附件、Lookup、部门选择、保存及恢复链路 | 当前 App 的请求适配器、字段控件、错误出口与类型 |
| 无容器的表单内容 | 只接收表单值、授权字段、控件参数及错误状态；不查询业务列表 | 使用宿主既有 UI 组件库渲染字段 |
| 任务详情公共包 | `ApprovalTaskDetail` 拥有任务加载、办理前核查、字段草稿、意见、动作及并发状态机 | 共用原 provider、字段渲染器、校验器和历史插槽 |
| 独立页面容器 | 路由定位、响应式布局、身份栏、页内反馈和成功／退出行为 | 宿主主题、返回／关闭能力及已确认产品文案 |

这些名称是职责划分，不是新增的 npm 导出。先核对 [公共包合同](package-and-list.md) 和实际安装产物；任务页使用已有 `renderLayout`，手机使用已验证的 sections/actionItems 插槽。不要复制包内 Controller。新建侧从宿主现有表单抽取共享能力，不虚构审批包的新建 API，也不为页面额外维护一套提交或授权算法。

### 按能力适配各 App

Skill 接入时先输出当前 App 的能力映射，再决定最小改动。按实际调用链识别能力，不以样板中的目录、组件名或 Hook 名作为匹配条件。

| 必须定位的能力 | 适配要求 |
| --- | --- |
| App／租户／环境／当前身份 | 沿用运行时、登录及请求层；不能从样板复制 appKey、域名或从 query 接受权限上下文覆盖 |
| 原新建表单与业务规则 | 复用字段联动、默认值、校验、附件、关联和保存前后业务逻辑；独立入口不能绕过原有写入规则 |
| START 配置与合并提交 | 沿用发起合同及已有 Service 适配；缺少接点时按接口合同补齐，不另造一个能绕过授权的“外部提交接口” |
| 字段控件及值转换 | 保留当前 UI 组件库、类型适配和错误反馈；新建与任务字段分别消费各自授权，自定义控件接到同一受控／序列化链路 |
| TASK 详情、附件、候选与动作 | 复用原公共包 provider 和节点元数据链路；尚未接入时按任务合同补齐，不复制样板项目的业务对象或权限集合 |
| 页面布局与完成行为 | 使用 App 自身主题和已确认体验；固定独立入口无业务菜单／列表，保留既有普通表单容器 |

模块化目录、React Hook 或具体字段控件可以因项目不同而变化。公共审批组件有其技术栈及版本前置条件，按实际公开产物核验；不满足时报告具体缺口，不为接入审批替换当前项目的技术栈。缺少字段适配、已确认的接口或业务规则时，先明确缺口，不能用普通文本框、普通 Schema 回退或假数据掩盖未完成接入。

独立路由位于业务工作台 Shell 之外，仍处于现有认证、权限和全局错误 Provider 内。保留身份显示及必要上下文，不挂载对象列表／我的审批列表、表格、筛选 Preset、分组或看板后再隐藏。可以将公共表单内容、共享表单 Hook 与两个容器分开；文件名和组件库沿用宿主约定。

表单保存通过完成回调交给容器：原抽屉沿用关闭／列表同步，独立页显示已保存或已提交结果，不能强制跳回列表或自动重新创建空白表单。任务办理的成功回调遵循 [按容器处理的任务合同](task-detail.md#办理成功后的容器行为)：独立页留在当前任务地址，重读最新详情与历史，旧动作立即失效；刷新失败保留已成功结果，只重试读取，不重复办理。取消／关闭及成功后的具体返回方式按宿主确认的体验配置；没有飞书／iframe 宿主桥合同的情况下，不自行增加 postMessage、window.close 或任意 returnUrl 跳转。

## 权限与生命周期

- BPM 新建先在全部候选对象中精确匹配 key；仅未命中 key 时，才按宿主兼容规则匹配名称并规范到 key 地址。不能在同一次 find 中混用 key/name 的 OR 条件，否则数组前方对象的名称可能抢占后方对象的真实 key。名称规范化保留 query/hash，未知对象不回退默认对象。已命中的 key 无权限或未绑定审批时不能再选同名对象；未配置有效 `bpmDefinitionKey` 时显示不可发起，不降级普通新建。
- 沿用 App、对象和创建操作权限；无需列表读取权限即可进入合法的新建入口。START 字段继续按 [发起合同](initiation-contract.md) 的 readable/editable 决定，不与普通 IAM createFields 求交。
- 任务页沿用 [TASK 合同](task-detail.md)。不能增加普通对象可读／可编辑权限作为合法任务访问的前置条件；完成、关闭或无有效动作的任务保留可见数据并只读，不能仅从流程状态判断。
- 配置、授权或元数据失败时阻止写入并提供原错误／重试，不从普通 Schema 补齐审批字段。权限反馈、加载与重试保持在独立页面内容区域，身份栏及全局错误出口持续可用。
- 用户、租户、App、环境、对象或任务切换时，取消／丢弃旧读取、字段草稿和迟到回调；部门选择返回后及每次创建／提交前复核会话仍有效。附件按下节逐次复核，不能只在整批上传完成后检查。合法配置刷新不能重置已保存 ID 或结果未知状态。
- 表单保存、保存并提交与原抽屉使用同一互斥／恢复规则；仅保存不发起，新建保存并提交只执行既有合并接口。提交结果未知时不得自动重试或重新创建。
- 离开或刷新页面时保护未保存输入；提交期间阻止重复操作。手机与桌面共享 Controller，字段展示按 makeui 的移动控件合同切换。

### 附件预上传的会话边界

- 保存尝试开始时捕获当前会话／身份／对象／流程绑定及权限快照，沿用宿主既有生命周期工具。每次预上传请求发出前、每次结果回填前及最终创建／提交前检查快照仍有效；同一字段内拆成多个文件请求时，每个请求也要检查。
- 在开始异步校验、部门选择或附件操作前建立可取消的会话所有权；卸载、撤权、切换目标／身份及流程绑定变化时取消在途预上传。通过既有请求适配器将 AbortSignal 传给实际上传请求，不绕开认证、Service、Trace 或后台授权。新尝试使用有效的新信号，不能复用已取消的控制器。
- 取消与会话复核必须同时存在。即使请求不响应取消而迟到返回成功，也不能回填旧表单、发出下一字段／文件请求或继续创建／提交；不展示旧会话的成功或业务失败提示。仍有效会话中的真实上传错误按原错误／重试规则处理，保留已经确认的上传结果。
- 取消不能回滚后台已完成的文件写入；创建／合并提交已发出后的结果仍按原保存会话和结果未知合同处理，不能因取消上传就宣布未创建或允许重新创建。

[安全边界参考](../assets/standalone-page-boundaries.mjs) 演示 key 优先和单次预上传前后复核，可对照宿主已有实现复用。示例导出不是公共 npm API，不要求 App 使用同名函数。会话捕获／取消、回填检查、批次迭代、最终写入与错误出口仍由原宿主控制器负责；参考函数通过不能代替真实 App 的回归。

## 接入与验证

1. 存量 App 先检查原表单业务逻辑、内容与其容器是否分离，再抽取共用部分；不整体复制某个样板工作台。新 App 直接保持控制器／内容／容器的分层。
2. 接入两个动态路径和地址构造函数，保留原新建入口及原审批列表行为。使用运行时对象 key、流程配置和显示名称，不能写死样板 App 的实体、字段、流程或域名。
3. 测试先覆盖：独立路由无 Shell／列表请求；未知对象不误入；key/name 冲突及名称规范化；仅创建权限；START 字段授权；普通保存与一次合并提交；未知结果防重复；任务按节点授权及已办只读；办理成功重读；多附件中途撤权／卸载及取消信号透传；身份切换、离开确认和重试。具体调用次数与反例见 [独立页验收矩阵](verification.md#bpm-独立页验收)。
4. 运行受影响的原抽屉、CRUD、审批列表／详情、字段及权限回归，再运行宿主构建和运行时门禁。
5. 真实浏览器与飞书 PC／移动端验证登录回跳、字段弹层、软键盘、滚动、底栏、附件及真实办理。代码／DOM 测试通过不代表飞书联调或真机验收完成。

Skill 更新指导生成及迁移，不会自动修改已发布 App。通用能力应由各 App 完成上述接入及回归后生效；源仓库改动、Skill 分发、App 接入和发布分别记录。

仓库的 `node scripts/test-bpm-standalone-pages-contract.mjs` 验证地址及跨 Skill 接线、成功回调的文档一致性、参考定位和异步取消行为，CI 的 `scripts/test-*.mjs` 循环自动执行。它不运行 App 页面，也不证明飞书已接通；宿主必须按验收矩阵调用自己的控制器／请求层验证。

每次完成一个 App 的接入，应交付实际能力映射、两个适用地址、复用／新增的接点，以及自动验证、真实飞书／浏览器验证和未解决缺口。样板用例通过不能替代其他 App 的验证；平台标准推广前，使用结构或组件库不同的 App 验证这份指导能否独立完成接入。只读比较其他 App 不等于已迁移或已通过该 App 的验收。
