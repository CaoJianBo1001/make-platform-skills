# 实体流程绑定独立查询

用于普通对象新建的审批分支、已有记录首次发起，以及 BPM 独立新建入口。Schema 只提供当前可访问对象和普通字段；流程绑定统一来自 Workflow，不回退 Schema 的同名扩展字段、DSL 或旧 Meta 接口。

## 接口与边界

```http
POST /make/workflow/v1/bpm-entity-definitions
X-Make-Target: MakeService.GetResource
Content-Type: application/json
```

```json
{"appKey":"sample_app","entityKeys":["claim","payment"]}
```

```json
{"code":200,"data":[{"entityKey":"claim","bpmDefinitionKey":"claim_approval"}]}
```

网关前缀沿用 Service 运行时：部署 `/make`、本地预览 `/api/make`，不硬编码域名。UI 经宿主认证请求层调用 Service；Service 从部署配置注入 appKey、转发可信登录／租户、Trace 和取消上下文，不接受浏览器覆盖租户、操作者、appKey 或流程 key。建议宿主路由 `POST /api/make/app/bpm/entity-definitions/query`，正文仅 `{entityKeys}`；存量命名以宿主 API 文档为准。

key 去除首尾空白、按首次出现去重。先取得当前权限过滤 Schema，只查询其中需要的对象；没有对象时跳过请求。Service 再校验请求范围，并拒绝返回的越界对象、重复对象或空流程 key。Workflow 不检查对象是否存在或对象权限，已删除对象也可能仍有绑定，因此不能用它发现对象或扩大权限。

仅启用且当前版本已部署的流程返回命中项；停用、草稿或未绑定的对象省略。成功 `data: []` 明确无绑定。HTTP 失败、HTTP 200 业务失败、无效响应均是错误，保留后端原因／错误码／Trace，不转换为空绑定。旧 `/make/meta/entity/query/bpm-definitions` 已移除；Schema 各接口不提供该能力。

## 宿主适配

- 为绑定建立独立于 Schema 的 `loading / ready / error` 状态及按 entityKey 索引的结果，不把 key 写回 Schema；共享一次当前范围的批量查询，避免列表每行请求。只有 ready 后的命中对象进入审批新建；ready 的未命中对象走普通新建。加载／失败期间阻止依赖绑定的创建、上传、保存并提交和首次发起，错误提供重试，不能降级普通 CRUD。
- 绑定不代表发起权限。Service 按下表区分操作，再核验相应权限与字段来源；不信任 UI 的分支或字段权限，不能以绑定替代 Workflow 最终校验。
- 普通列表、读取、已有记录普通编辑及历史不因绑定查询失败而整体不可用；原 IAM、记录状态与锁规则继续执行。审批导航、待处理／已完成／已发起、任务／实例详情、历史及合法撤回不依赖当前对象是否仍绑定流程。
- 应用、环境、身份、权限或 Schema 范围变化时取消旧查询并丢弃迟到结果；刷新清除旧绑定的可用资格，不以旧快照继续保存。沿用宿主已有刷新／重新打开表单机制，不新增后台轮询或跨身份绑定缓存。
- 对依赖当前绑定的创建／首次发起会话，在异步校验、部门选择、每次附件上传和最终写入／发起之前均复核当前会话。绑定变化使这些旧操作失效并取消可取消请求；已保存记录 ID、已确认附件和写入结果未知状态不能因绑定刷新被清空，不能因此重建记录或重发结果未确认的写请求。普通记录更新保持原链路，不因绑定刷新失去编辑资格。

### 刷新、取消与写入结果的顺序

1. 绑定刷新开始即推进会话代次并使旧操作失效；即使刷新后流程 key 相同，旧异步步骤也不能继续。可以使用宿主已有 generation／请求所有权标识，不要求固定变量名，不能仅按 key 是否变化判断有效性。
2. 创建／合并提交已经发出后，取消不代表未写入。迟到的可靠成功结果先按写请求所有权确认并记录到原保存会话，保留记录 ID 和已确认附件，再停止过期步骤及其后续发起或 UI 完成回调；不能先因过期而丢掉可靠 ID，也不能让旧新建回调改用普通更新继续写入。其他身份、租户、App 或对象的新表单不得接收该结果。
3. 写入结果未知保护与对应写请求绑定。写请求尚未发出时，校验、部门选择、预上传失败或取消不新增写入结果未知状态，也不清除原先尚未确认的其他写请求保护。旧保存回调再次执行、迟到错误或 finally 均不能清除原保护、解锁别的请求或恢复新建资格；只有该写请求的可靠结果或已确认的核查结果才能确认其结果。保留原错误原因，不自动重发。
4. 绑定代次只取消依赖当前绑定的创建／首次发起步骤。合法撤回使用自己的实例定位、授权和取消所有权，不随绑定刷新取消；普通已有记录编辑也不依赖绑定代次。身份切换、卸载等仍遵守各操作本身的生命周期。

### 按操作选择授权

下表的“查询”指 Service 在该操作边界重新核验当前有效绑定；“不依赖”表示不得把绑定查询或新建字段配置作为该操作的前置条件。

| 操作 | 当前绑定 | 字段及操作授权 | 执行路径 |
| --- | --- | --- | --- |
| 新建保存／保存并提交 | 查询 | 应用、对象、新建操作 IAM；命中时按 START 同次 formMetadata 及 readable/editable，未命中普通保存按 createFields／IAM；失败不降级 | 仅保存走原创建；保存并提交走一次 bpm-process-submit |
| 新建预上传／START Lookup | 查询 | START 当前字段授权及类型，保留关联目标读取权限 | 复用原预上传／候选编排 |
| 已有记录直接发起 | 查询 | 对象资格与记录状态；发起资格交 Workflow，不读取 START 配置、不附加普通 CRUD 权限 | 对原 recordId 调用 bpm-process / CreateResource，沿用发起部门选择 |
| 已有记录普通编辑 | 不依赖 | 原 IAM、记录状态和锁；不套用启动字段授权 | 原普通更新；编辑后发起只在保存成功后独立执行上一行 |
| 任务详情／办理 | 不依赖 | 当前任务 fieldPermission/actions 与同次 bpm-task 的 formMetadata | 原任务读取与动作，不经普通记录更新 |
| 实例详情／历史／合法撤回 | 不依赖 | 实例／历史／撤回自身的 Workflow 访问与动作资格 | 原实例、历史及撤回接口 |

已有记录发起、普通编辑和撤回的细节见 [记录生命周期](record-lifecycle.md)。不能把审批新建的 START 字段读取或 data.record.create 门禁复用为已有记录发起的前置条件。

## 验证

在宿主现有测试中先复现再改造：Schema 没有 key 而查询命中；Schema 残留旧 key 而查询为空／失败；多个对象部分命中及全空；删除或不可访问对象不查询；无对象不请求；HTTP 与业务错误保留原因并可重试；身份／环境／权限切换时旧请求迟到；部门选择或首个附件期间绑定替换后后续上传和写入为零；绑定刷新不丢已保存 ID／未知写入保护；解绑后历史、锁与任务页仍可用。

同 key 刷新、可靠成功响应迟到、未知结果保护及旧保存回调重入，按 [宿主时序桥接合同](binding-session-verification.md) 接入真实控制器并运行随包验证器；静态规则检查不能代替这些行为证据。

字段来源继续使用 [发起合同](initiation-contract.md)，请求映射见 [Workflow 接口](workflow-api.md)，普通权限见 [权限 Skill](../../make-app-permission/SKILL.md)。此指南适用于各 App 的现有技术栈与能力，不要求复制样板目录、组件名或业务字段，也不代表存量 App 已自动迁移。
