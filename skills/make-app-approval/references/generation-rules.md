# 默认生成规则

在需求方案确认后、项目生成前判断；迭代增加能力时重新检查。生成规则以本文件随包提供的合同为准。

## 按业务能力判定

| 方案中的实际能力 | 生成“我的审批” | 依据 |
| --- | --- | --- |
| 用户新增、录入或编辑并保存业务记录 | 是 | 面向使用者的业务写入，例如申请填写、客户登记、销售目标录入 |
| 明确要求审批、审批待办或审批处理 | 是 | 即使没有新增申请页，也需要个人任务入口 |
| 看板与业务写入并存，或多对象中只有一个可录入 | 是，只生成一个 | 应用级能力，不按每个对象重复生成 |
| 纯查询、只读列表、统计看板、展示 | 否 | 没有业务写入或审批处理 |
| 仅登录、搜索、筛选、查询条件输入 | 否 | 输入控件不等于保存业务记录 |
| 仅定义数据表/对象，没有录入、编辑或审批功能 | 否 | 数据模型不等于用户操作能力 |

判断依据是已经确认的功能方案，不能以是否包含“表单”“提交”“审批”等词代替语义判断。不要把“提交搜索条件”误判成提单，也不要漏掉没有审批字样的业务录入应用。数据库初始化、开发脚本写入不构成面向使用者的业务写入。

输出简短的依据清单：对象 → 用户动作 → 是否触发 → 新增/复用的入口。没有这些能力时记录“不生成”的理由即可，不主动扩展需求。

## 生成与复用

- 一个 App 一个稳定的导航标识和路由，桌面/手机共用。复用宿主已有审批路由；新项目按自己的命名规范选择固定路由，例如 `/approvals`，不要按对象创建多个审批中心。
- 入口以应用访问资格为前提，不作为普通业务对象的 `meta.entity.read` 菜单项；保留既有登录、应用范围及后端任务数据授权。入口可见不授予业务记录或其他人的任务权限。
- 决策结果进入宿主导航/路由配置，不能在渲染时通过 `entities.some(bpmDefinitionKey)`、当前任务数、某个对象是否可写重新决定入口是否存在。
- 初次生成尚无流程绑定时也保留入口；以后绑定、发布、启用、停用、解绑或调整流程无需再次生成导航。已有历史任务的入口和直达路径继续可用。
- 对已经包含业务新建功能的方案，同时生成运行时 Schema key 判定、启动配置读取、字段分支、保存/首次发起及状态适配。当前无有效 key 时这些能力走普通保存分支；后续配置生效后，刷新/重新打开表单即可切换审批字段和按钮，无需 AI 再改代码。不预置假的 key、字段配置或流程定义。只有审批处理、没有新建页的方案只生成其已有业务界面所需接点，不扩大业务范围。
- 后续迭代新增写入或审批能力时补齐缺失入口；多对象、多次生成及不同终端复用同一应用级入口。纯查询应用已有历史入口时，本规则不自动删除它。
- 各对象保留自己的记录列表。不要生成跨表单“我的申请”、独立草稿箱或跨应用任务中心。

## 导航层级与位置

- “我的审批”是独立的应用一级入口，与业务对象/模块分组处于同一最外层。不得作为任何对象、模块、可折叠分组或子菜单的子项，也不放进“更多”折叠菜单。
- 桌面/平板侧栏将它作为一级菜单，紧接当前可见的所有业务对象/模块分组之后，放在同一导航列表与滚动区域内，沿用普通菜单行间距。例如依次展示“合同台账、履约节点、付款计划、我的审批”，审批项与前一项之间不留大块空白，也不单独增加分隔线、卡片或底部区域。由 [makeui 的侧栏布局](../../makeui/references/app-shell-layout.md) 实现；“对象下方”指菜单排列顺序，不是侧栏或视口底边。
- 不用 fixed/sticky、`margin-top: auto` 或弹性占位把审批项推到底部。导航超长时，业务菜单与审批项共同在侧栏内滚动，审批项可以随滚动移出可视区；不得把它设为始终可见的固定页脚，也不引入整页滚动。
- 展开/折叠对象或模块分组只改变其子项，审批项始终是分组外的一级兄弟项，随着前方菜单高度自然移动；对象排序或增减后仍排在业务入口之后。宿主已有侧栏整体收窄模式时，仍保留可点击的审批图标及可识别名称提示。
- 迭代发现已有审批入口被嵌入对象分组，或被固定在侧栏底部并单独分隔时，将同一入口移到业务入口之后的一级菜单位置，去掉为审批添加的固定区域、分隔和占位。保留原路由和导航标识，移除旧位置的重复入口；不要再新增第二个审批入口。
- 手机为“我的审批”保留一个独立底部 Tab，不归属某个对象，作为底部业务入口的最后一项计入导航数量。总数不超过五项，有 AI 时从 4 个业务对象起展示工作台，无 AI 时从 5 个起展示；顺序为业务对象、我的审批、可用的 AI 助手、需要时的工作台。完整顺序、容量和宿主组合示例以 [makeui 的移动导航规范](../../makeui/references/mobile-defaults.md#底部导航与工作台) 为准；没有生成审批入口的应用沿用原有导航规则。

## 任务中心交付

触发默认生成后，完整接入按 [包与列表](package-and-list.md)、[任务详情](task-detail.md) 和 [历史](history.md) 交付真实任务中心，不能止于导航占位。

- 宿主已有任务中心：入口连接现有页面，复用真实加载、失败和无任务空态。
- 宿主尚无任务中心：安装兼容审批包、适配控件与 provider、接通 Service 和详情动作。仅在用户明确只做导航，或真实依赖暂不可用时保留“审批中心暂未接入”说明；这属于未完成项，不能宣称完整交付。不能连接空链接、404、静态任务列表，或将未接接口伪装成“暂无任务”。
- 只有真实查询成功且结果为空才能显示无任务空态。后续包接入沿用该入口，不新增第二个导航。

手机布局和任务页交给 [makeui](../../makeui/SKILL.md)，不把桌面菜单或表格直接缩放到手机。
